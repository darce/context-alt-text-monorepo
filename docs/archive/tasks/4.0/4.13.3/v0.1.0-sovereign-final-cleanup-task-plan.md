# 4.13.3 -- v0.1.0 Final Cleanup: Phases 2-4 Execution

## Problem Statement

Phases 1-3 of the WordPress Sovereign Cluster Architecture (v0.1.0) are mostly merged or code-complete, but the "hard dependency removal" (Phase 4) and full cleanup of deprecated fields (Phases 2-3) are outstanding. Residual `thumbnail_url` references in PHP mappers and React components break the "sovereign" principle and lead to dead code rot.

## Workflow Principles

- **Greenfield Policy**: Clean rewrites over shims. No Alembic schema migrations (baseline already updated).
- **Sovereign Read-Model**: The plugin must derive all display data from local MySQL tables and media library URLs; `thumbnail_url` is obsolete.
- **Backend-First**: The backend already stopped emitting these fields; the plugin must now stop expecting them.

## Terminology

- **Local Projection**: The `wp_acx_*` tables mirroring backend state.
- **Sovereign Facade**: A local service replacing runtime HTTP proxies for reads.

## Current State Analysis

- Backend baseline migrations already removed `thumbnail_url`.
- Plugin `ClusterFacade` is implemented but response mappers still include `thumbnail_url` keys (Phase 2 incomplete).
- Frontend TypeScript types and components still reference `thumbnail_url` and `cluster_thumbnails` (Phase 3 not started).
- Documentation at `wp-sovereign-cluster-epic.md` and architecture diagrams are out of sync with current sovereign reality (Phase 4 not started).

## Proposed Solution

Execute a cross-layer sweep to remove the last ~40 references to `thumbnail_url` and `cluster_thumbnails`. Then, update the Epic and architecture contracts to reflect the completed state of v0.1.0.

## Patterns to Follow

### Removing Field from PHP Response Mapper

```php
// Remove this:
'thumbnail_url' => $this->resolve_thumb_url( $member_row, $media_id ),
```

### Collapsing Frontend URL Resolution

```tsx
// Before
const rawUrl = representative.thumb_url ?? representative.thumbnail_url ?? null;

// After
const rawUrl = representative.thumb_url ?? null;
```
