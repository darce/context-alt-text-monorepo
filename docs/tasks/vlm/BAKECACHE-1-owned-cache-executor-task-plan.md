## Lifecycle, cleanup and refusal semantics

State machine: `VALIDATED → LEASED → RESERVED → FETCHING → VERIFIED → COLLECTOR_ARMED → BOUND → RUNNING → STOPPING → EXIT_PROVEN → UNLOAD_PROVEN → CLEANED → SEALED → RELEASED`. A terminal error branches to STOPPING if any child exists, otherwise to owned partial cleanup; no transition skips ownership proof. Journal transitions before/after side effects for interruption recovery; after the pre-seal snapshot/close, journal only in the still-writable batch state. Terminal publication follows observed seal/release disposition, outside the leg, and is not another ExecutionState or a required pre-seal write. Catch ordinary exceptions and SIGINT/SIGTERM; use bounded finally teardown. SIGKILL/power loss cannot guarantee immediate cleanup: next invocation treats an unresolved lease/journal, missing terminal publication, or uncertain seal/release acknowledgement as blocked even if the lock FD closed or C reports released. Explicit owned reconciliation revalidates reserved directory/attempt/lease identities, stopped writers, the preseal digest/entry/byte snapshot, actual seal and C ledger release disposition under the same proofs before publishing a missing final outcome. Never infer release from lock availability or replay the action/cleanup/release on uncertain evidence; inability to re-establish any proof keeps can_advance=false. A previously published terminal file is immutable: validate it or refuse, never overwrite it to repair history. No automatic stale PID kill.

Spawn server with `start_new_session=True`, record process identity and group; supervise downloader and action subprocesses as well. Stop with TERM to the proven owned group, wait finite grace, KILL only after identity revalidation, reap the direct child and verify no tracked/group members remain. Direct-child `wait()` alone is insufficient for surviving children. Record each return code/signal; unknown exit (`EXIT_UNPROVEN`) or ownership mismatch blocks unload/eviction/advance. Expected executor-initiated TERM may be a known teardown result; unrequested early signal/nonzero exit is failure. Retain original run/scorer error as well as cleanup errors.

On real target, poll admitted device backend for absence of owned process allocations and release of attributable runtime allocation; device total need not be zero. If backend cannot prove unload, set `UNLOAD_UNPROVEN`, preserve cache and resource lock disposition for reconciliation, and forbid next arm. Fixture backend can prove synthetic unload only, never target GPU unload.

After exit/unload proof, mark server's component-use sublease inactive. Keep the **exclusive slot lock** while deleting only ledger-owned inactive regular component/partial files and releasing reservation files. Recheck ownership/inodes immediately before unlink; no globs, shared cache eviction, user-weight deletion or recursive unknown tree removal. Successful, error and interrupted runs use the same teardown/cleanup. Verify the free-byte/headroom receipt, persist pre-seal evidence and stop/close leg writers, seal the leg, then call release_slot and retain its actual Outcome in the batch state before terminal publication. Physical FD closure alone is not a successful release receipt. This distinguishes ending active model use from releasing the slot lock: releasing the exclusive lock before eviction would admit a racing next writer. If any cleanup/seal/release/publication proof fails or remains unknown, `can_advance=false`; close process on exit but leave durable blocked state that the batch consumer and a new lock holder must honor pending explicit reconciliation. Never amend a sealed leg to record these later observations.

Typed terminal reasons include `INVENTORY_INCOMPLETE`, `HASH_MISMATCH`, `PATH_UNSAFE`, `OWNERSHIP_UNKNOWN`, `LEASE_BUSY`, `SPACE_INSUFFICIENT`, `RESERVATION_UNPROVEN`, `TARGET_ADMISSION_MISSING`, `SUBPROCESS_MISSING`, `READINESS_TIMEOUT`, `RUN_FAILED`, `SCORE_FAILED`, `EXIT_UNPROVEN`, `UNLOAD_UNPROVEN`, `CLEANUP_UNPROVEN`, `COLLECTOR_UNAVAILABLE`. Distinguish optional measurement unavailability (run may be preserved as partial) from required admission/unload proof (no advance). Report no PASS for unknown ownership/hash/exit and no quality PASS from executor success.
