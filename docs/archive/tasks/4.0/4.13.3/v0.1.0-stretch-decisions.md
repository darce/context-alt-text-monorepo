# v0.1.0 Stretch Goal Decisions

## `acx://` URI Indirection
**Decision**: **KEEP** URI indirection for v0.1.0.

**Rationale**:
- **Abstraction**: `acx://` provides a clean boundary between domain identifiers (Identity UUID, Cluster UUID) and WordPress physical storage (Attachment ID, Thumb sizes).
- **Flexibility**: If the plugin later supports external CDN storage or multiple thumb variants, the indirection layer (`resolve_thumb_url`) can handle it without changing the persisted projection data.
- **Agentic Efficiency**: Coding agents can reason about `thumb_path` as a stable domain handle rather than calculating physical URLs or attachment metadata in every component.

---

## Naming Unification (`thumb_url` vs Scoped Fields)
**Decision**: **DEFER** full normalization to `thumb_url`.

**Rationale**:
- **Ambiguity**: In complex response envelopes (e.g., `PendingSuggestion` which has both `identity` and `representative`), a top-level `thumb_url` is ambiguous. Scoped fields like `identity_thumb_url` and `representative_thumb_url` are more explicit.
- **Consistency vs Complexity**: While single-object responses (like `ClusterResponse`) could use a bare `thumb_url`, keeping the scoped naming (`representative_thumb_url`) remains consistent with the suggestion payloads.
- **Action**: Normalization will be revisited in `v0.2.0` when the unified DTO strategy is implemented.

---

## Snapshot Endpoint Polish Scope
**Target Milestone**: `v0.1.1` or `v0.2.0` (depending on tenant scale).

**Defined Scope**:
1. **Cursor-based Pagination**: Implement `cursor` and `page_size` in `get_snapshot` to avoid memory spikes and timeouts for 10k+ identity tenants.
2. **Atomic Versioning**: Ensure `snapshot_version` remains locked for the duration of a multi-page pull.
3. **Failure Hardening**: Explicit `503 Retry-After` handling in the backend when DB load is high during snapshot generation.
4. **Compression**: Enable Gzip compression for snapshot payloads to reduce egress costs and transfer time.
