## Outcome and settled decisions

The original installation goal was an authenticated, isolated remote development service with a **working 512D in-house FIR path**, matching vector database and real self-hosted descriptions. Continue from the installed sites and accepted runtime evidence above. Keep the existing 128D YuNet/SFace stack as a reproducible comparator; per the 2026-09-21 operator choice it is optional, not a prerequisite for the AuraFace512 route. The final quality milestone is not satisfied by dimension alone.

The 512D route starts with exact-artifact qualification of AuraFace-v1 through ONNX, using the in-house runtime/identity pipeline without InsightFace runtime or buffalo weights. A 512D artifact is a development target, not a guarantee of better recognition. If artifact review fails, stop that candidate and record the replacement decision. Never silently substitute a different model. Detector improvement and encoder capacity are separate workstreams; **detection is the first quality experiment**.

Already settled: LocalWP plus isolated remote service/DB; no public WP endpoint required for FIR development; self-hosted VLMs only; reuse FIR-16/VLM-6 and FIRBENCH; paired clustering visualizations; codemap discovery and semantic `handoff.db` prior art. The explicit current remote model/effort/FAST launch receipt supersedes historical worker pins. Do not ask settled architecture questions again. No PG19 prerequisite, production cutover or broad weight-training campaign belongs to this wave.

Functional completion, measured quality and production approval are distinct. A working 512D development route can be delivered and honestly marked unqualified for production when quality evidence is inadequate. It must still pass artifact, isolation and functional correctness checks. Retain an explicit 128D comparison endpoint; never create an automatic cross-model fallback.

## Three technical boundaries that must stay explicit

**Detector versus recognizer.** A missed face never reaches SFace/AuraFace or clustering. Independently annotate whole images; require one-to-one spatial matches, not matching face counts. The original S3a requirement rejects count-only fallback in new detector comparisons while preserving labeled historical replay; consume the merged strict scorer rather than reopening its implementation. Report clean, mask, sunglasses, hand/object and mixed cells, size/pose controls, FPPI and uncertainty. Reference boxes plus reference landmarks are a combined geometry intervention when both change; do not call the resulting gain pure detector improvement. The withdrawn 0.504/0.995 comparison is not valid independent recall evidence.

**128D versus 512D storage.** Each model space includes exact weights, preprocessing/alignment contract, normalization and distance, not just dimension. Preserve the installed isolated stores and their vector/centroid schema and API/worker manifests. A new model-space experiment requires fresh compatible embeddings from pixels; never import SFace vectors, buffalo vectors or stale cluster IDs across spaces. Keep 128D resources separate and explicitly selectable for comparison. PG19 cannot repair representation or detection quality.

**Diagnosis versus acceptance.** Legacy data supports diagnosis. Candidate operating points are selected on calibration and frozen before evaluation. Detector adoption requires an agreed recall gain, clean-face floor, FPPI and latency policy; recognizer adoption requires correct identification at a fixed false-identification budget and gallery protocol. Null budgets, missing labels and insufficient independent evidence mean unqualified. Cluster projections are diagnostic; compute scores in the original space. Description evaluation separates supported facts, coverage, identity/position errors, usefulness, latency and actual versus estimated cost.
