    entropy=int(base_interval_seed), spawn_key=(), pool_size=4

## Arithmetic, ordering and final rounding

The hash-bound incorporated §7 is the formula authority. Its ratio derivation and safe normalization are written in ASCII here for readability:

`a_j = S_j/M`, `p_j = M_j/M`, `delta_hat = sum_j a_j`, `r_j = a_j - delta_hat*p_j`, `V_hat = [K/(K-1)] sum_j r_j^2`, `SE_hat = sqrt(V_hat)`.

The reference stage order is fixed. After ordered face accumulation and the K check, visit j ascending to check M_j > 0 and |S_j| <= M_j and accumulate observed S and M. Form a_j then p_j for each j ascending; sum a_j left to right from zero to obtain delta_hat (exactly S/M); then form r_j, square it and add its square left to right from zero. Multiply the completed squared-residual sum by exact K/(K-1) to obtain V_hat. No SE conversion precedes the exact V_hat check. For each tuple, visit slots ascending to check the gathered invariants and sum gathered S and M, then form a_star and p_star in that order for every slot, accumulate a_star to delta_star, and form/square/accumulate residuals in slot order before applying the same K/(K-1). Next form n_b = delta_star - delta_hat, classify exact V_star and n_b, and for positive V_star compute n_b squared divided by V_star for comparisons. Only certified quantities contribute diagnostics; a failed tuple contributes solely its numeric_failure count. Stage completion precedes any downstream stage; no floating reassociation or parallel reduction changes this reference order.

Every operation up to square roots is exact rational arithmetic with arbitrary-size integers; denominators are positive, fractions are reduced with positive denominator, and rational zero has one canonical representation. Do not square unnormalized floating totals. Reject K<2 before any division by K-1. Accepted weights may total beyond binary64 range internally. Zero tolerance is exactly zero; a tiny positive rational variance stays positive.

For positive V_star, let `n_b = delta_star - delta_hat`. Represent finite t as its sign and exact rational square `n_b^2/V_star`; do not round a square root or t to choose a category, histogram bin or rank. Order negative t values by decreasing squared magnitude, zero next, positive values by increasing squared magnitude. Order -infinity first and +infinity last. Finite values equal exactly when signs and squared magnitudes agree, with both zero categories in one t=0 equivalence class. For a deterministic total sort, break equal-t ties by original b ascending. The tie breaker never changes the quantile value or the B denominator. Compare histogram edges by exact sign and squared magnitude as well.

Selected finite q is retained as an exact symbolic t value. Endpoints are `delta_hat - SE_hat*Q(19/20)` and `delta_hat - SE_hat*Q(1/20)` without intermediate rounding. For a selected positive-variance draw the correction is equivalently `n_b*sqrt(V_hat/V_star)`; for either finite-zero category the correction is exactly zero. This single signed-radical expression permits exact comparison against every binary64 rounding boundary: first decide the sign of the rational difference, then compare nonnegative rational squares; never square across an unresolved sign. Equality with a boundary is decided exactly. A reference implementation can search the finite ordered set of binary64 rounding cells using those comparisons; no precision/tolerance schedule is needed. Square-root diagnostics use the same exact nonnegative-square comparison. Round final finite endpoints **once**, IEEE-754 binary64 round-to-nearest, ties-to-even, including subnormal and overflow boundary rules. Exact zero emits +0.0. A required nonzero endpoint rounding to zero, or any endpoint rounding to a nonfinite value, is endpoint-phase numeric failure. No clipping to [-1,1].

Required endpoints and optional diagnostics have different failure effects. Rule E from incorporated §11 emits a diagnostic iff its correctly rounded binary64 is finite and is zero exactly when its exact value is zero; otherwise emit null. A finite exact t too large for binary64 is still a finite ranked t, with diagnostic null, never a tagged infinity. A positive exact SE below binary64 range stays usable internally, with diagnostic null. Optional diagnostic null never causes method refusal or changes ranks. JSON serialization uses `allow_nan=False`; status strings, not numeric/string pseudo-infinities, encode selected infinite quantiles.

The normative reference uses exact arithmetic and the finite rounding-cell decision above.
