# ORTTEL-1: outbound egress audit (infra and CI)

## Verdict

The scoped infrastructure has several expected outbound paths: dependency and container downloads, model seeding, GitHub Actions logs/caches, OCI control-plane and registry calls, Tailscale deployment access, and Caddy ACME certificate issuance. The ONNX Runtime v1.28.0 privacy note documents telemetry only for Windows builds; this checkout locks 1.29.0 and deploys Linux runtime images, so that note does not confirm telemetry is active on the runtime image. Keep `ORT_DISABLE_TELEMETRY=1` as defense-in-depth for future upgrades. Hugging Face Hub telemetry is conditional on a library call and has no explicit opt-out configured. A separate operator-local Grok offload path is documented as held off because its CLI may upload the active checkout's Git objects to Google Cloud Storage; the repository proxy blocks that host but is not wired into the launcher. OCI security lists allow all outbound IPv4 traffic, so the host/network layer does not constrain these paths. No Sentry, Datadog, PostHog, or comparable agent/configuration was found in the scoped compose, systemd, deployment, or workflow files.

## Recommended switches and placement

- Set `ORT_DISABLE_TELEMETRY=1` in `apps/prototype-description-service/Dockerfile` at `runtime-base` so recognition and VLM descendants inherit it. The checked Dockerfile currently lacks it. For externally supplied images, set it in `docker-compose.env.yml` for both API and worker.
- Set `HF_HUB_DISABLE_TELEMETRY=1` in `runtime-base` and in any host-side VLM seed/provision environment. `HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1` already belong to `runtime-vlm` and prevent Hub requests in that serving stage; they do not cover the seed command.
- Keep `NOTIFY_WEBHOOK_URL` empty when remote notifications are not needed. Limit webhook templates to non-sensitive status text.
- Keep Grok offload disabled until the proxy runs automatically with every Grok CLI invocation; a shallow clone protects old Git history but does not stop the active checkout reaching an external host.
- For less broad network egress, replace `0.0.0.0/0` security-list egress with required endpoints or an egress proxy. Preloading images/models and using package mirrors removes repeated third-party fetches.
- If public ACME contact is undesirable, configure supplied certificates or a private Caddy issuer in `Caddyfile`; keep public HTTPS certificate issuance in mind.
- CI cache uploads can be removed by deleting `actions/cache` steps; workflows can be disabled or narrowed by event/path filters. Use a controlled runner if hosted-runner cache/log retention is not acceptable.

## Gaps

- `Makefile.d/` is absent in this checkout. No `.env` deployment secrets or live OCI configuration were available, so actual registry overrides, webhook URLs, tailnet status, and per-region endpoints are unknown.
- No runtime packet capture was performed. This is a static configuration/source audit; actual telemetry frequency, destination hostnames, and payloads are not observable here.
- `uv.lock` selects ONNX Runtime 1.29.0. The cited v1.28.0 privacy note says telemetry was implemented only for Windows builds in that release; it does not establish whether telemetry is active on the locked Linux runtime image. Runtime telemetry activity, payload, and destination hostname were not verified.
- The managed Hugging Face Hub package is the locked 0.36.2 and confirms the telemetry helper and opt-outs. Locked Transformers source was not installed, so its actual telemetry call sites are unverified.
- `docker-compose.demo.yml` runs WordPress and the demo env example sets `WP_AUTO_UPDATE_CORE=true`; WordPress.org update-check/download behavior and the actual deployment setting were not verified from the image/source. `WP_AUTO_UPDATE_CORE=false` disables automatic core upgrades, but should not be treated as proof that all update-check requests stop.
- `ACX_GPU_ENDPOINT_URL` is operator-configurable, and the application-level egress behavior beyond the infrastructure paths above was not audited. The first-party recognition/description services are not vendor rows.
