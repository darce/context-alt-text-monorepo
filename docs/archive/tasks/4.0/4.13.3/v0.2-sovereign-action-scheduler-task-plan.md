# Plan: v0.2 -- Action Scheduler Migration for Sovereign Sync

## Problem Statement
The current sync logic is manual and lacks built-in retry mechanisms, backoff strategies, or concurrency control. This makes the system fragile to transient network issues or backend timeouts.

## Workflow Principles
- **Async Execution**: Sync operations must not block the main PHP process or UI rendering.
- **Robust Retries**: Exponential backoff must be used for all 5xx and 429 response codes.

## Terminology
- **Action Scheduler**: A library for WordPress that provides a scalable, background-processing task runner.
- **Sync Job**: A specific background task responsible for either pulling a snapshot or pushing outbox operations.

## Current State Analysis
- Sync pulls are currently manual or triggered synchronously via `SyncPullJob`.
- There is no automated retry logic for failed sync attempts.
- Large snapshot pulls can time out or exceed PHP memory limits without batching.

## Proposed Solution
Migrate snapshot pulls and outbox syncs to the WordPress Action Scheduler library for robust, background-processed task orchestration with built-in retry logic.

## Patterns to Follow

### [Action Scheduler Hook Pattern]

```php
// Registering an AS action
as_enqueue_async_action( 'acx_sovereign_sync_pull', [ 'tenant_id' => $tenant_id ] );

// Handling the action
add_action( 'acx_sovereign_sync_pull', function( $tenant_id ) {
    // Sync logic here
}, 10, 1 );
```
