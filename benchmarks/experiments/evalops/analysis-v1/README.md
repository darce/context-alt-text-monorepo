# Operational error analysis v1

This is a descriptive, unvalidated coding of the latest 240 `agent_errors` records in the frozen handoff.db extract, not 240 episodes or production application traffic. The records sum to 400 stored occurrences; the producer's aggregation and duplicate semantics are not established. The manifest freezes the query, observation time, range and input digest. Selection is a latest-record cutoff, not a probability sample; older records, successful operations, missing capture and application traffic are outside the frame. Sampling weights and inclusion probabilities are unknown. No healthy control is inferred from silence.

The open-code pass precedes the axial map. It uses ordered symptom phrases, then retains a source-class code marked uncertain when no phrase matches. It covers 240 records (197 phrase-supported and 43 uncertain), with no claim of independent human coding, causal truth, or expert validation. The axial file maps each original open code without replacing it; unmapped and uncertain observations must remain visible. Codes describe logged symptoms, not adjudicated failures. In particular, similar compaction and embedding messages may share a cause, but neither matching text, time nor task alone proves one incident. Each record has a stable placeholder group ID, while `incident_group_id` and cross-record links are unknown. No root-incident deduplication is justified by this extract; placeholders are not an incident count. A future deduplication needs explicit trace/retry or incident evidence, recorded membership and rationale, including unresolved links. The original summaries remain intact in the restricted input snapshot, referenced by ID and summary hash; no raw summary is copied here. The canonical full-row hash allows exact recovery and conservation checks without publishing sensitive text. The source file itself must be retained with the handoff for those checks.

The 128 write-rejection, 54 compaction and 31 embedding *records* are different native telemetry populations from the historical 441-item taxonomy; no trend or causal comparison follows. A record's occurrence count is not a count of independent tasks or incidents. Existing 58/57/5 human labels are partly user-adjudicated, not independent gold. No labeling, acceptance, live runtime or production reliability claim follows from this analysis.

Proposed metrics, only after complete, comparable operation-level instrumentation and a frozen time window exist:

- Rejected-write rate: rejected write attempts / all eligible attempted writes, including successes, in the same window and population. Define retry identity and rejection outcome first.
- Failed-compaction rate: failed compaction attempts / all initiated compaction attempts, including successful attempts, on the same capture basis.
- Failed-embedding-query rate: failed embedding query attempts / all initiated embedding queries, including successes, with timeout and retry policy pinned.

These denominators, capture completeness, stable operation identities, missingness and retry linkage are unavailable here; rates are therefore not calculated. Preserve null for unknown usage. Report coverage and gaps alongside any future metric, and avoid treating repeats as independent cases.
