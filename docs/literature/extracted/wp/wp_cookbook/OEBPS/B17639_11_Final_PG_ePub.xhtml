Chapter 11: Fetching, Caching, and Regularly Updating External Site Data

After spending most of our time learning how to extend WordPress to allow site administrators and users to create local content, this chapter focuses on interacting with external data sources. While we did some work with displaying Twitter feed content in the Creating a new shortcode with parameters recipe in Chapter 2, Plugin Framework Basics, we had very little control over how this data was displayed since the content was shown in an IFrame. We also had no control over how this data was fetched and no way to cache it. The reason for this is that every user loading a page containing the Twitter feed shortcode fetched their own copy of the information to be displayed.

There are many different types of data out there that we could be interested in fetching, caching, and displaying. In this chapter, we will be focusing on two different types of information: RSS feeds and generic XML data.

More specifically, we will learn how to work with external data through the following recipes:

  • Displaying RSS items from an external feed
  • Optimizing plugin performance by storing external data using transients
  • Scheduling plugin data updates using WP-Cron

Technical requirements

You can find complete code examples on GitHub in the following repository: https://github.com/PacktPublishing/WordPress-Plugin-Development-Cookbook-Third-Edition.

Displaying RSS items from an external feed

RSS is a technology that has been around since the early days of the internet. Its main purpose is to allow users to be easily notified when new content is published on their favorite sites. The underlying mechanism behind RSS feeds is a simple XML file that contains the site's headlines along with updated timestamps and part or all of the content of new items that are posted. Applications or services called RSS aggregators (for example, Feedly and NewsBlur) can monitor the content of RSS feeds and display new items as they are published or notify users of this new content. It is interesting to note that podcasts use the same RSS feed technology to publish their episodes online.

While RSS is not as popular as it used to be, most news-based websites still publish RSS feeds. WordPress includes a copy of the SimplePie library to allow developers to easily fetch and cache RSS feed data and easily display it on a site.

            if ( $feed_items ) {

                foreach ( $feed_items

                          as $index => $item ) {

                    if ( 0 == $index ) {

                        $output .= '<h3>' .

                        $item->get_feed()->get_title() .

                }

How it works...

This recipe uses a lot of the tools that we covered in previous chapters to add a new menu item in the Settings menu, define a configuration page for our new plugin, and save the information that the user provides. That being said, it does introduce one new concept in the configuration page with input fields that all share the same name including square brackets (rss_feed[]). This standard nomenclature is used to indicate that all form fields with this name are to be collected and sent to the processing code as an array. Looking at the process_ch11rf_options function, we can see that our code checks to see whether we have received any data in the $_POST['rss_feed'] variable. If data is found, our code cycles through all entries with a foreach loop. Each URL found is escaped and stored in the site option table using a single array.

Our recipe also creates a new shortcode called [rss-feeder] to display our RSS feed data. The main new element in this code is the fetch_feed function. This function takes the URL of an RSS feed as its only argument and returns a SimplePie object. Once we've executed the fetch_feed function, we check that the return value is not an error using the is_wp_error function. We then use the get_items method of the object to retrieve the 5 most recent items of the feed and iterate through all items with a foreach loop. The feed items themselves also offer multiple methods. We are calling these throughout our shortcode display function to get access to the information that they contain (get_title, get_permalink, get_description, and get_feed).

There's more…

In addition to facilitating the retrieval of RSS items from a remote site, the fetch_feed function also has built-in caching capabilities.

Changing the fetch_feed caching period

By default, any RSS data retrieved with the fetch_feed function will be saved in the WordPress site database using a caching mechanism called transients for a period of 12 hours. This means that the first time you try to access the page, it will take more time to appear as the server fetches all data and processes it before displaying it onscreen. Any subsequent visit during the next 12 hours will come up much faster. That being said, it will also show the exact same news items as the first visit. As with most aspects of WordPress, this caching period can be modified with a filter callback function. For example, adding the following code to the plugin file changes the caching period to 1 hour (3,600 seconds):

function ch11rf_feed_cache( $seconds ) {

    return 3600;

}

add_filter( 'wp_feed_cache_transient_lifetime',

            'ch11rf_feed_cache' );

The wp_feed_cache_transient_lifetime filter always sends and expects to receive a value in seconds.

Optimizing plugin performance by storing external data using transients

Some WordPress functions, such as the fetch_feed function that we saw in the Displaying RSS items from an external feed recipe, offer a built-in caching mechanism. This is not the case when building custom code to retrieve information from other online data sources. The following recipe takes a look at using the public API of a transportation agency, Bay Area Rapid Transit, in the San Francisco area. It shows how to retrieve and cache remote XML data in our local site database using transients to speed up site performance while also alleviating the load on the remote data source.

Getting ready

You should have access to a WordPress development environment.

How to do it...

Follow these steps to query, cache, and display transit data from an external source:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Create a new directory called ch11-transit-feed.
  3. Navigate to the directory and create a text file called ch11-transit-feed.php.
  4. Open the new file in a code editor and add an appropriate header at the top of the plugin file, naming the plugin Chapter 11 – Transit Feed.
  5. Insert the following block of code in your code file to define a utility function, is_multi_array_or_convert, which will check whether the variable it receives is a multidimensional array and make it one if it isn't:

    function is_multi_array_or_convert( $array ) {

        if ( isset( $array[0] ) &&

                is_array( $array[0] ) ) {

            return $array;

        } else {

            return array( $array );

        }

    }

  6. Add the following block of code to the end of the plugin file to create a second utility function, get_transit_data, which will be responsible for fetching data from the Bay Area Rapid Transit website:

    function get_transit_data() {

        $stations = array( '12th', '16th',

                           '19th', '24th' );

        $transit_data = array();

        foreach ( $stations as $station ) {

            if ( false === ( $transit_data[$station] =

                get_transient( 'transit_feed_'

                               . $station ) ) ) {

                $next_departures_xml =

                    simplexml_load_file(

             'http://api.bart.gov/api/etd.aspx?cmd=etd&orig='

                     . $station . '&key=MW9S-E7SL-26DU-VV8V' );

                $next_departures_json =

                    json_encode( $next_departures_xml );

                $transit_data[$station] =

                    json_decode(

                        $next_departures_json, TRUE );

                set_transient( 'transit_feed_' . $station,

                    $transit_data[$station], 300 );

            }

        }

        return $transit_data;    

    }

  7. Insert the following line of code at the end of the plugin file to define a new shortcode:

    add_shortcode( 'transit-feed',

                   'ch11tf_transit_feed' );

  8. Insert the following block of code to define the ch11tf_transit_feed function:

    function ch11tf_transit_feed() {

        $output = '';    

        $transit_data = get_transit_data();

        if ( empty( $transit_data ) ) { return; }

        $output .= '<div class="transit-feed">';

        foreach ( $transit_data as $station_data ) {

            $output .= '<h3>';

            $output .= $station_data['station']['name'];

            $output .= '</h3>';

            if ( empty(

                    $station_data['station']['etd'] ) ) {

                continue;

            }

            $etd_array = is_multi_array_or_convert(

                $station_data['station']['etd'] );

            $output .= '<table><tr><th>Destination</th>';

            $output .= '<th>Direction</th>';

            $output .= '<th>Number of minutes</th></tr>';

            foreach ( $etd_array as $etd ) {

                if ( empty( $etd['estimate'] ) ) {

                    continue;

                }

                $etd_estimate_array =

                    is_multi_array_or_convert(

                        $etd['estimate'] );

                foreach ( $etd_estimate_array as $eta ) {

                    $output .= '<tr><td class="dest">'

                        . $etd['destination']

                        . '</td><td>' . $eta['direction']

                        . '</td><td>' . $eta['minutes']

                        . '</td></tr>';

                }

            }

            $output .= '</table>';

        }

        $output .= '<style>';

        $output .= '.transit-feed th {text-align: left}';

        $output .= '.transit-feed table { width: 100% }';

        $output .= '.transit-feed .dest { width: 40% }';

        $output .= '</style>';

        $output .= '</div>';

        return $output;

    }

  9. Save and close the plugin file.
  10. Navigate to the Plugins management page and Activate the Chapter 11 – Transit Feed plugin.
  11. Go to the Pages section of the administration area and click on Add New to create a new page.
  12. Insert the [transit-feed] shortcode in the page editor, Publish the page, and click on View Page.

How it works...

The bulk of the work in this recipe is done by the get_transit_data utility function. When called by our shortcode, this function first defines an array of abbreviated station names and an empty array of transit data. It then proceeds to loop through the station names array and uses an if statement that contains both a condition and an assignment statement:

if ( false === ( $transit_data[$station] =

            get_transient( 'transit_feed_'

                           . $station ) ) ) {

If we first look at the part of this code in the innermost parentheses, it calls the get_transient function and inserts the result as a new member in the $transit_data array. It uses the abbreviated station name as the array key. The transient name passed to the get_transient function also uses this abbreviated station name, along with a static string. Now, the actual conditional if statement is that we check if the value returned by get_transient and assigned to the array is the value false. If it is, no transient data was found under that name or the data has expired.

In the case where no data is returned by get_transient, we use the standard PHP simplexml_load_file function to get data from the public transit website and store it in a local variable. We then use a coding trick with the json_encode and json_decode functions to easily convert the XML object received from the simplexml_load_file function to a simpler PHP multidimensional array. We store the result in the $transit_data array, using the station code as the array key.

Last but not least, our utility function calls set_transient to store each station's data in the WordPress transients system with an expiration time set to 300 seconds. While this might not seem like much, it will still prevent a lot of data retrieval from the public transit site as well as speeding up page loads on a high-traffic website. It can also greatly help stay within limits when working with data services that have a maximum number of times you can access their services on an hourly or daily basis. While we could have gone for a longer period, we don't want the scheduling data to go completely stale either. Once all station data has been retrieved from the transient tables or refreshed, the resulting transit data array is returned.

Note

We could have saved the entirety of the transit data array in a single transient. We made the choice to store it in separate transients for each station to show that transient names don't have to be fixed strings. This approach could also be beneficial if we wanted to display individual station data on separate pages.

The remainder of the recipe implements a shortcode that requests the transit data from our utility function and renders it nicely to appear on our website. In addition to looping through all data and generating HTML, the shortcode implementation uses our second utility function, is_multi_array_or_convert. This function helps us make the data received from the public transit website more uniform. This is required since the site sends back a multidimensional array when multiple departures are found or a simple array of individual fields for single departures. Our utility function returns a multidimensional array either way. We can then easily loop through the results without needing to check how the data is structured.

Scheduling plugin data updates using WP-Cron

When working with external data sources, it's always important to consider the frequency and mechanism used to update this data, as well as caching data locally. While our code in the Optimizing plugin performance by storing external data using transients recipe is functional, it only checks whether the transient data is expired when users visit the shortcode. This slows down the page display if new data has to be fetched and processed. A better approach is to schedule our data update function to be periodically executed when any part of the site is visited, or even on a very specific schedule using WP-Cron.

Getting ready

You should have already followed the Optimizing plugin performance by storing external data using transients recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch11/ch11-transit-feed/ch11-transit-feed-v1.php) from the book's GitHub page and rename the file as ch11-transit-feed.php.

How to do it...

Follow these steps to schedule our data update function so that it retrieves new transit data without requiring visits to the page containing the [transit-feed] shortcode:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Navigate to the ch11-transit-feed directory and edit ch11-transit-feed.php.
  3. Add the following block of code at the end of the plugin file to register a function to be called when the plugin is initialized:

    add_action( 'init', 'ch11tf_init' );

  4. Insert the following code to provide an implementation for the ch11tf_init function:

    function ch11tf_init() {

        add_action( 'ch11tf_transit_data_update',

                    'get_transit_data' );

        register_deactivation_hook( __FILE__,

            'ch11tf_deactivation' );

        if ( !wp_next_scheduled(

                'ch11tf_transit_data_update' ) ) {

            wp_schedule_event( time(), 'five_minutes',

                'ch11tf_transit_data_update' );

        }

    };

  5. Add the following block of code to the end of the plugin file to provide an implementation for the ch11tf_deactivation function:

    function ch11tf_deactivation() {

        wp_clear_scheduled_hook(

            'ch11tf_transit_data_update' );

    }

  6. Go to the end of the plugin file and add the following block of code to register a function with the cron_schedules filter:

    add_filter( 'cron_schedules',

                'ch11tf_add_cron_period' );

  7. Insert the following block of code to provide an implementation for the ch11tf_add_cron_period function:

    function ch11tf_add_cron_period( $schedules ) {

        $schedules['five_minutes'] = array(

            'interval' => 300,

            'display' => 'Five Minutes'

        );

        return $schedules;

    };

  8. Save and close the plugin file.
  9. Click on the Add New menu item found in the Plugins section of your site administration page.
  10. Search for the Advanced Cron Manager plugin, then click Install Now and Activate.
  11. Go to the Tools menu and select Cron Manager.

How it works...

WP-Cron provides a set of functions that allow developers to schedule the execution of custom code in the background as website visits take place.

The first of these functions is wp_schedule_event, which registers an action to be executed regularly on the website where it is activated. It should be noted that this is the first time that we are assigning an action instead of a function to execute our code. This means that we need to use the add_action function to associate our get_transit_data utility function to a new action hook, ch11tf_transit_data_update, before we can schedule it.

Once this is done, we use a WP-Cron utility function called wp_next_scheduled to check whether our custom action has already been scheduled before scheduling it. This must be done since wp_schedule_event schedules the given action blindly even if that exact hook was scheduled before.

When finally calling wp_schedule_event, its three parameters indicate the timestamp when the action hook should be executed next, the frequency for subsequent executions, and the name of the action hook to run, respectively. The timestamp that is most often sent for the first parameter is the return value of the standard PHP time() function. The result is that the action immediately runs before following its assigned schedule. When it comes to the execution frequency parameter, the four default periods in WordPress are hourly, twicedaily, daily, and weekly. The five_minutes frequency that we specify in our recipe is a custom period that is created through the cron_schedules filter hook, where the actual duration is specified in seconds.

The third WP-Cron function that we use in our recipe is wp_clear_scheduled_hook, which is placed in the plugin's deactivation function callback. It is very important to call this function to remove the action hook from the table of actions to be executed. Otherwise, that task will keep running, even if the plugin is deleted.

Once our action hook is registered with WP-Cron, it will check if it needs to be executed based on the specified schedule every time a site page is visited. On a highly visited site, this will help regularly update transit data.

There's more…

WP-Cron can be improved beyond its initial capabilities with a few additional manipulations.

Improving WP-Cron execution

WP-Cron helps check for out-of-date external data more frequently than only when the page displaying this data is viewed. That being said, site visits might not be frequent enough on a low-traffic site to keep the data updated. The built-in WP-Cron system also has an execution cost when any web page is visited since it needs to check if a scheduled task needs to run every single time.

To improve the WP-Cron system, a site owner can use a more reliable mechanism to schedule regular execution of data update code. This can be done using their own web server's cron functions or an external service through the following steps:

  1. Edit the site's wp-config.php file and add the following line of code above the line that says stop editing:

    define( 'DISABLE_WP_CRON', true );

  2. Create a cron job on your web server to call the following command at the desired frequency, where YOUR_SITE_URL would be replaced with your site address:

    wget --delete-after http://YOUR_SITE_URL/wp-cron.php

    Note

    Note that we are not providing exact steps to create a cron job as this will vary depending on your web server configuration and available management tools.

    We should also mention that free and paid third-party services (for example, https://www.easycron.com/ and https://cron-job.org/en/) can also be used to access this special URL on a regular schedule.
