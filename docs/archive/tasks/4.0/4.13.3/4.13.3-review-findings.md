## MEDIUM Findings

### M-1: Status filter reuses page-size CSS class names

- **File:** `apps/prototype-wp-alt-context/js/admin/pages/workbench/MediaSelection.tsx`
- **Lines:** 148-177
- **Description:** The status filter `<Select.Root>` uses `acx-media-selection__page-size-*` class names (`page-size-trigger`, `page-size-icon`, `page-size-content`, etc.) instead of dedicated `acx-media-selection__status-filter-*` classes. Both selects share identical class names, preventing independent styling.
- **Fix:** Rename to `acx-media-selection__status-filter`, `__status-filter-trigger`, `__status-filter-icon`, `__status-filter-content`, `__status-filter-viewport`, `__status-filter-item`, `__status-filter-indicator`.
- **Status:** [x] Fixed (2026-02-20)

### M-2: `_doing_it_wrong` receives `__METHOD__` instead of `$method` parameter

- **File:** `apps/prototype-wp-alt-context/src/sovereign/repositories/trait-prepares-sql-queries.php`
- **Line:** 70
- **Description:** `log_empty_tenant_id_guard(string $method)` accepts a `$method` parameter (which callers pass as their own `__METHOD__`), but then calls `_doing_it_wrong(__METHOD__, ...)` which always resolves to `PreparesSqlQueries::log_empty_tenant_id_guard`. The diagnostic message should identify the actual caller method.
- **Fix:** Change `__METHOD__` to `$method` in the `_doing_it_wrong()` call.
- **Status:** [x] Fixed (2026-02-20)

### M-3: Unreachable `is_array()` guard in `do_sync`

- **File:** `apps/prototype-wp-alt-context/src/sovereign/sync/class-sync-pull-job.php`
- **Line:** 48
- **Description:** `SnapshotClient::fetch_snapshot()` returns `array|WP_Error`. After the `is_wp_error()` check at line 44 passes, `$snapshot` is necessarily `array` via type narrowing. The `! is_array($snapshot)` guard at line 48 is unreachable dead code.
- **Fix:** Remove the `is_array()` guard or add a comment explaining defensive intent. If the return type is truly `array|WP_Error`, the guard is provably dead.
- **Status:** [x] Fixed (2026-02-20)

### M-4: `resolve_sync_pull_job` re-attempts construction on every call after failure

- **File:** `apps/prototype-wp-alt-context/src/api/class-sync-status-controller.php`
- **Lines:** 126-155
- **Description:** When `SyncPullJob` construction throws, the method catches the exception and returns `null`, but does NOT set `$this->sync_pull_job` to a sentinel value. On the next call, `null !== $this->sync_pull_job` is still false, so construction is re-attempted. This is either (a) an intentional retry or (b) a missing sentinel. If construction fails due to a persistent condition (e.g., missing config), every `trigger_sync` call will re-throw and re-log.
- **Fix:** Set `$this->sync_pull_job` to a sentinel (e.g., a NullSyncPullJob implementing the interface) in the catch block, or document the retry-on-every-call behavior as intentional.
- **Status:** [x] Fixed (2026-02-20)
