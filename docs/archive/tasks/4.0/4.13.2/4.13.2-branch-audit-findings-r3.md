## HIGH Severity

### R3-H-1 . Snapshot transport uses wrong request policy (circuit contamination)

|              |                                            |
| ------------ | ------------------------------------------ |
| **Files**    | `apps/prototype-wp-alt-context/src/sovereign/sync/class-snapshot-client.php` L27-29 |
| **Category** | ANTIPATTERN                                |

`SnapshotClientTransport::request()` calls `proxy_request($method, $path, $body, $query)` with only 4 args, so the 5th parameter `request_class` defaults to `'auto'`. For GET requests, `resolve_request_policy('GET', 'auto')` maps to the `ui_read` policy:

| Policy attribute     | `ui_read` (current) | `background_sync` (correct) |
| -------------------- | -------------------- | ---------------------------- |
| `timeout_seconds`    | **2**                | 30                           |
| `max_retries`        | **1**                | 3                            |
| `circuit_enabled`    | **true**             | false                        |

**Two consequences:**

1. **Spurious sync failures.** A full cluster snapshot must complete within 2 seconds. Any network latency or large payload causes a timeout.

2. **Circuit contamination.** `build_circuit_breaker_key()` uses `md5($base_url)` -- the same key for all policies. Two consecutive failed snapshot fetches open the circuit breaker, blocking **all** UI reads for 60 seconds.

**Fix:**

```php
// class-snapshot-client.php L27-29
public function request( string $method, string $path, array $body = array(), array $query = array() ): WP_REST_Response|WP_Error {
-   return $this->proxy_request( $method, $path, $body, $query );
+   return $this->proxy_request( $method, $path, $body, $query, 'background_sync' );
}
```

Also add a test verifying `SnapshotClientTransport` uses `background_sync` policy parameters.
