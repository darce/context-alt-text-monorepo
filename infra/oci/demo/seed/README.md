## Layout

```text
infra/oci/demo/seed/
  README.md          this file
  import.sh          wp-cli import (synced to the VM by scripts/deploy/sync-demo.sh)
  media/             JPEG/PNG inputs (not committed until licensed)
  clustering-manifest.txt   `<slug> <count>` written by select-clustering-seed.sh
  guided-manifest.txt       `<slug> <count>` written by select-guided-seed.sh
  select-clustering-seed.sh celebs01 top-N selection (SEED-PROVENANCE block)
  select-guided-seed.sh     guided-prototype people (GUIDED-PROVENANCE block)
```

Generate the clustering seed with `select-clustering-seed.sh` (default 20 persons
× 5 images = 100, jpg/jpeg/png only) before running `import.sh`:

```bash
SRC=/Users/daniel/Development/altcontext-marketing-monorepo/static/input-images/celebs01 \
  PERSONS=20 PER_PERSON=5 bash infra/oci/demo/seed/select-clustering-seed.sh
```

It copies images into `media/` (uncommitted; see `media/.gitignore`), writes
`clustering-manifest.txt`, and regenerates the provenance table above. The walkthrough
runbook names expected roster labels for E2E assertions.

Then add the guided-prototype people (no `SRC` needed — sources are in the repo):

```bash
bash infra/oci/demo/seed/select-guided-seed.sh
bash infra/oci/demo/tests/verify-clustering-seed.sh   # counts both manifests
```

`verify-clustering-seed.sh` expects `media/` to hold exactly the clustering set plus the
files listed in `guided-manifest.txt`; `scripts/deploy/tests/test-guided-seed.sh` pins the
selector's contract (runs under `python3 -m pytest scripts/deploy/tests/test_guided_seed_shell.py`).

## Import

`make deploy-demo` (scripts/deploy/sync-demo.sh) ships `seed/import.sh` and any
licensed `seed/media/` files to `/opt/acx-backend/demo/seed/`. On the VM after
bootstrap:

```bash
cd /opt/acx-backend/demo
./seed/import.sh
```

Or from repo checkout during development:

```bash
DEMO_DIR=/opt/acx-backend/demo ./infra/oci/demo/seed/import.sh
```

## Enrol the guided people in the live roster (operator step)

`import.sh` only creates attachments. Naming Katy Perry and Justin Trudeau in the live
roster is a curation write on the demo database, so it stays an operator step — run it
after the import and Workbench scan (walkthrough runbook §2), authenticated as a user with
`can_manage_roster`, with `X-WP-Nonce` from `wp.apiFetch` or an application password.

1. Create the roster entries (`409` means the name already exists — reuse that id):

   ```bash
   curl -sS -X POST "$WP/wp-json/acx/v1/roster/persons" -H "Content-Type: application/json" \
     -u "$WP_USER:$WP_APP_PASSWORD" -d '{"name":"Katy Perry","tags":["guided-prototype"]}'
   curl -sS -X POST "$WP/wp-json/acx/v1/roster/persons" -H "Content-Type: application/json" \
     -u "$WP_USER:$WP_APP_PASSWORD" -d '{"name":"Justin Trudeau","tags":["guided-prototype"]}'
   ```

   Each response carries the new `id` (this is the `roster_entry_id` below).

2. Find the cluster ids the scan produced for the `katy_perry_*` and `justin_trudeau_*`
   attachments — Workbench → Clusters, or `GET $WP/wp-json/acx/v1/roster/entries` and the
   cluster list. The `tribeca_press_1.jpg` faces should land in the same two clusters; if
   they split, commit the larger cluster and merge the remainder in Workbench.

3. Commit each cluster to its entry:

   ```bash
   curl -sS -X POST "$WP/wp-json/acx/v1/roster/clusters/$CLUSTER_ID/commit" \
     -H "Content-Type: application/json" -u "$WP_USER:$WP_APP_PASSWORD" \
     -d "{\"roster_entry_id\": $ROSTER_ENTRY_ID}"
   ```

4. Verify: describe `tribeca_press_1.jpg` from the Media Library; the live panel should
   name both people. The guided prototype's live panel (`acx_guided_live_media_id`) can then
   point at that attachment id.

Nothing here runs from CI or the deploy pipeline: `sync-demo.sh` ships the media and
`import.sh` unchanged, and the roster write is deliberate.

## Enable the public guide (operator step)

`deploy-demo` does **not** turn on the signed-out walkthrough. Enabling
`/guide/` is a deliberate per-site operator step after the stack is up:

```bash
make demo-enable-public-guide WP_PATH=/opt/acx-backend/data/demo-wpdata SITE_URL=https://demo.altcontext.com
DRY_RUN=1 make demo-enable-public-guide WP_PATH=/opt/acx-backend/data/demo-wpdata SITE_URL=https://demo.altcontext.com
```

That runs `scripts/deploy/enable-public-guide.sh`: `wp option update acx_public_guide_enabled 1`,
`wp rewrite flush --hard`, then a signed-out GET of `<site>/guide/` must return 200 with
`id="acx-public-guide"`. The public demo describe endpoint (`/acx/v1/public/demo/describe`,
gated by `acx_public_demo_enabled`) stays **off** unless you explicitly retain it with
`ACX_RETAIN_PUBLIC_DEMO_DESCRIBE=1`.
