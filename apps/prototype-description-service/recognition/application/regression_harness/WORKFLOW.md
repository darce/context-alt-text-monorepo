# Canonical Report Workflow (Regression Harness)

This document describes the end-to-end workflow to:

- Generate a **canonical report** (ground-truth labelled clusters) from the DB.
- Measure clustering **false positives / false negatives** (pairwise, permutation-invariant).
- Visualize **predicted vs canonical** cluster structure and understand **outliers**.

## Definitions

- **Canonical cluster**: an `identity_clusters` row with `user_confirmed=true` and a **non-empty** `label`.
- **Canonical report**: JSON generated by `scripts.generate_canonical_report` that serializes canonical clusters using
  stable `IdentityLocator` keys (`media_id` + bbox fields).
- **Predicted cluster**: the algorithm output from a single clustering run **before manual curation**.
- **Outlier / unclustered identity**: a `media_identities` row with **no** `identity_members` row (no cluster
  assignment).

## 1) Run clustering (create a baseline run)

Trigger clustering for a tenant/dataset using the service API (UI is fine too). The simplest is the sync endpoint:

- `POST /clustering/jobs` with `{"tenant_id": "<TENANT_UUID>", "mode": "sync"}`

Record the returned clustering job id (this is `identity_clustering_jobs.id`).

## 2) Find the `recognition_runs.id` for that clustering job

The regression harness attaches a `recognition_runs` row to the clustering job. Query it (example SQL):

```sql
SELECT id, status, created_at, started_at, completed_at, clustering_job_id
FROM recognition_runs
WHERE tenant_id = '<TENANT_UUID>'::uuid
  AND clustering_job_id = '<CLUSTERING_JOB_ID>'::uuid
ORDER BY created_at DESC
LIMIT 1;
```

The `id` returned here is the `--run-id` you should pin into the canonical report so it can reconstruct the
pre-curation predicted state from `recognition_events`.

## 3) Curate and label clusters (ground truth)

Use the cluster UI/API to:

- Rename clusters to their final human label.
- Merge/split/reassign identities until each label corresponds to one real entity.

Important constraints from `report_builder.generate_canonical_report()`:

- Only clusters with `user_confirmed=true` are considered.
- Empty/blank labels are ignored.

If a cluster doesn’t appear in the canonical report, verify it’s confirmed and has a non-empty label.

## 4) Generate `canonical_report.json`

Run from `apps/prototype-description-service/`:

```bash
python -m scripts.generate_canonical_report \
  --tenant-id <TENANT_UUID> \
  --run-id <RUN_UUID> \
  --dataset-name "optional name" \
  --dataset-notes "optional notes" \
  --output data/canonical_reports/<TENANT_UUID>/<RUN_UUID>.json
```

Notes:

- If you omit `--media-id-file` and provide `--run-id`, the report uses `recognition_runs.dataset_selector.media_ids`
  as the dataset filter (so the report stays aligned to the run that produced the predicted events).
- `pre_curation_state` is only included when `--run-id` is provided.

## 5) Measure false positives / false negatives

The harness’s primary regression metric is **pairwise precision/recall/F1** over identity pairs:

- **False-positive pairs**: `predicted_pairs - true_positive_pairs`
- **False-negative pairs**: `ground_truth_pairs - true_positive_pairs`

Coverage note: evaluation is only meaningful for identities present in the canonical report. If you leave many identities
unlabeled/unconfirmed, they will be absent from `canonical_clusters` and therefore excluded from the metrics.

### Option A: Evaluate immediately after clustering (DB snapshot)

This pulls predicted clusters from the **current DB state**, so run it **before any manual curation changes**
(merges/splits/reassignments) that mutate `identity_members`.

```bash
python -m scripts.evaluate_run \
  --canonical data/canonical_reports/<TENANT_UUID>/<RUN_UUID>.json \
  --tenant-id <TENANT_UUID> \
  --output data/evaluations/<TENANT_UUID>/<RUN_UUID>.json
```

### Option B: Evaluate later using `pre_curation_state` (frozen snapshot)

If you generated the canonical report with `--run-id`, it contains `pre_curation_state.predicted_clusters`, which can
be evaluated offline (even after curation) without reading predicted state from the mutated DB.

One-liner example (run from `apps/prototype-description-service/`):

```bash
python - <<'PY'
import json
from pathlib import Path
from recognition.application.regression_harness.metrics import compute_pairwise_metrics
from recognition.application.regression_harness.serialization import load_canonical_labels
from recognition.domain.locator import IdentityLocator

report_path = Path("data/canonical_reports/<TENANT_UUID>/<RUN_UUID>.json")
payload = json.loads(report_path.read_text())

canonical_labels = load_canonical_labels(report_path)
predicted = {}
for cluster in (payload.get("pre_curation_state") or {}).get("predicted_clusters", []):
    cluster_id = cluster.get("predicted_cluster_id")
    for locator_payload in cluster.get("member_identity_locators", []):
        predicted[IdentityLocator.from_dict(locator_payload)] = str(cluster_id)

missing = sorted(canonical_labels.keys() - predicted.keys(), key=lambda loc: (loc.media_id, loc.bbox_x, loc.bbox_y))
for i, locator in enumerate(missing):
    predicted[locator] = f"unclustered:{i}"

metrics = compute_pairwise_metrics(canonical_labels=canonical_labels, predicted_clusters=predicted)
fp_pairs = metrics.predicted_pairs - metrics.true_positive_pairs
fn_pairs = metrics.ground_truth_pairs - metrics.true_positive_pairs
print({**metrics.__dict__, "false_positive_pairs": fp_pairs, "false_negative_pairs": fn_pairs})
PY
```

## 6) Visualize clusters and outliers

### A) Predicted ↔ canonical mapping graph (recommended)

Build a bipartite graph (canonical labels ↔ predicted clusters) to spot:

- **Fragmentation**: one label spread across many predicted clusters (false negatives).
- **Contamination**: one predicted cluster mixing many labels (false positives).
- **Outliers**: canonical identities missing from predicted clusters (treated as `unclustered:*` above).

Quick-start (writes `cluster_mapping.dot` + `cluster_mapping.svg` in the current directory):

```bash
python - <<'PY'
import json
from collections import Counter, defaultdict
from pathlib import Path

from recognition.application.regression_harness.serialization import load_canonical_labels
from recognition.domain.locator import IdentityLocator

report_path = Path("data/canonical_reports/<TENANT_UUID>/<RUN_UUID>.json")
payload = json.loads(report_path.read_text(encoding="utf-8"))

canonical_labels = load_canonical_labels(report_path)

predicted = {}
for cluster in (payload.get("pre_curation_state") or {}).get("predicted_clusters", []):
    cluster_id = str(cluster.get("predicted_cluster_id"))
    for locator_payload in cluster.get("member_identity_locators", []):
        predicted[IdentityLocator.from_dict(locator_payload)] = cluster_id

counts = defaultdict(Counter)  # label -> Counter(predicted_cluster_id | "UNCLUSTERED")
for locator, label in canonical_labels.items():
    counts[label][predicted.get(locator, "UNCLUSTERED")] += 1

labels = sorted(counts.keys())
label_ids = {label: f"L{i}" for i, label in enumerate(labels)}

pred_values = sorted({pred for counter in counts.values() for pred in counter.keys()})
pred_ids = {pred: f"P{i}" for i, pred in enumerate(pred_values)}

dot_lines = [
    "digraph ClusterMap {",
    "  rankdir=LR;",
    "  node [fontsize=10];",
]
for label in labels:
    dot_lines.append(f"  {label_ids[label]} [shape=box, label={json.dumps(label)}];")
for pred in pred_values:
    shape = "octagon" if pred == "UNCLUSTERED" else "ellipse"
    display = pred if pred == "UNCLUSTERED" else pred[:8]
    dot_lines.append(f"  {pred_ids[pred]} [shape={shape}, label={json.dumps(display)}];")
for label in labels:
    for pred, count in counts[label].most_common():
        dot_lines.append(f"  {label_ids[label]} -> {pred_ids[pred]} [label={json.dumps(str(count))}];")
dot_lines.append("}")

Path("cluster_mapping.dot").write_text("\n".join(dot_lines) + "\n", encoding="utf-8")
print("wrote cluster_mapping.dot")
PY

dot -Tsvg cluster_mapping.dot -o cluster_mapping.svg
```

Interpretation tips:

- If a canonical label connects strongly to **many** predicted clusters, that label is fragmented.
- If a predicted cluster connects to **many** canonical labels, that predicted cluster is contaminated.
- The `UNCLUSTERED` node shows canonical identities that never landed in any predicted cluster (outliers).

### B) Explain *why* identities became outliers (events)

When you pin a `--run-id`, the run’s `recognition_events` include `assignment_decision` payloads (decision, reason,
threshold, stage, etc.). Use them to see which gate checks caused rejections:

```sql
SELECT
  payload->>'reason' AS reason,
  COUNT(*) AS reject_count
FROM recognition_events
WHERE tenant_id = '<TENANT_UUID>'::uuid
  AND run_id = '<RUN_UUID>'::uuid
  AND event_type = 'assignment_decision'
  AND payload->>'decision' = 'reject'
GROUP BY payload->>'reason'
ORDER BY reject_count DESC;
```

### C) Spot borderline members (optional)

To find cluster members whose stored similarity falls below their cluster threshold:

```bash
python scripts/audit_cluster_quality.py --tenant-id <TENANT_UUID> --limit 200
```

### D) Inspect the current outlier set (UI/API)

The clusters API supports an outlier “pseudo-cluster” view that surfaces unclustered identities:

- `GET /clusters?include_outliers=true`

Use it to sanity-check how many identities remained unassigned after a run (and to drill into which ones).
