Chapter 12: Enabling Plugin Internationalization

WordPress is a worldwide phenomenon, with users embracing the platform all around the globe. To create a more immersive experience for users in different locales, WordPress offers the ability to translate all of its administrator- and visitor-facing content. Like most other functionalities on the platform, internationalization is also available to plugin developers. By calling a set of easy-to-use functions, developers can include translation files with their creations.

To prepare a plugin to be localized, developers must use special internationalization functions when dealing with any textual element. Once this structure is in place, any site administrator can create localizations by themselves for languages that they are familiar with. They can submit these translations back to the plugin author for inclusion in a future update to the extension. WordPress.org also offers an online interface for users to be able to contribute translations without requiring the use of offline tools (https://translate.wordpress.org/).

This chapter explains how to prepare a plugin to be translated. It also shows how to use the Poedit tool to create a new language file for a simple plugin through the following topics:

  • Changing the WordPress site language configuration
  • Adapting default user settings for translation
  • Making admin page code ready for translation
  • Modifying shortcode output for translation
  • Translating text strings using Poedit
  • Loading a language file in the plugin initialization

Technical requirements

You can find complete code examples on GitHub in the following repository: https://github.com/PacktPublishing/WordPress-Plugin-Development-Cookbook-Third-Edition.

Changing the WordPress site language configuration

The first step to translate a plugin is to configure WordPress to a language setting other than English. This will automatically trigger mechanisms in the platform to look for alternate language content for any internationalized string.

Getting ready

You should have access to a WordPress development environment.

How to do it...

Follow these steps to configure the site to display in French:

  1. Open your development site's Dashboard and navigate to the General section of the Settings menu.
  2. Set Site Language to Français du Canada and click on Save Changes.

How it works...

The WordPress Site Language configuration option allows administrators to select the language that will be seen by visitors when they go to your website. It also determines the language that will be assigned to administrators by default when they visit the management section of the site.

As can be seen in the drop-down list of languages, WordPress has a single language installed by default, shown at the top of the list. The remainder of the list indicates languages that can be added to your website. When you set a new language, translation files are automatically downloaded for the selected language and the new selection becomes the default for visitors. If you look inside the wp-content/languages directory of your WordPress installation, you will see that a number of files with .po, .mo, and .json extensions were downloaded for the selected language. Portable object (.po) files are ASCII text files that contain a list of translations between the original English text from the WordPress source code and a target language. Machine object (.mo) files are binary versions of portable object files that can be efficiently loaded by PHP as a website is rendered. Finally, JavaScript Object Notation files (.json) contain translation text for some of the newer components of the WordPress administration interface.

Note

If you are not presented with a list of languages to install automatically in the General section of your development site's Dashboard, visit https://wordpress.org/support/article/installing-wordpress-in-your-language/ to learn how to manually download and install translation files for WordPress.

Adapting default user settings for translation

Before we can create translation files for our own plugins, their code needs to be specifically written to allow text items to be translated. This work starts in the plugin's activation routine, where default plugin option values are set. By using translation functions, our code can search for alternate values when a language other than English is specified in the website's configuration file.

Getting ready

You should have already followed the Changing the WordPress site language configuration recipe to have configured a language other than English for your development site.

How to do it...

Follow these steps to assign a translated string to a plugin's default options array on initialization:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Create a new directory called ch12-hello-world.
  3. Navigate to the directory and create a text file called ch12-hello-world.php.
  4. Open the new file in a code editor and add an appropriate header at the top of the plugin file, naming the plugin Chapter 12 - Hello World.
  5. Add the following line of code to register a function to be called when the plugin is activated:

    register_activation_hook( __FILE__,

        'ch12hw_set_default_options_array' );

  6. Insert the following block of code to provide an implementation for the ch12hw_set_default_options_array function:

    function ch12hw_set_default_options_array() {

        if ( false === get_option( 'ch12hw_options' ) ) {

            $new_options = array();

            $new_options['message'] =

                __( 'Hello World',

                    'ch12hw_hello_world' );

            add_option( 'ch12hw_options', $new_options );

        }

    }

  7. Save and close the plugin file.
  8. Navigate to the Plugins management page (Extensions in French) and click on the Activate link (Activer in French) for the Chapter 12 - Hello World plugin.
  9. Use your development server's database administration tool (phpMyAdmin, Adminer, or another) to run the following query against your site database:

    SELECT * FROM wp_options where option_name =

    'ch12hw_options'

Figure 12.1 – Hello World plugin options shown in Adminer

As seen in Figure 12.1, a new options array was created in the database, containing a default value for a message.

How it works...

The __ function (that's two underscores) is a WordPress internationalization utility function. When called, it tries to locate a translation for the text that it receives in its first argument within the text domain specified in the second argument. A text domain is essentially a subsection of the global translation table that is managed by WordPress. In this example, the text to be translated is the string Hello World, for which the system tries to find a translation in the ch12hw_hello_world domain. Since this domain is not available at this time, the function returns the original string that it received as its first parameter. The plugin code assigns the value it receives to the default configuration array.

It should be noted that the __ function is an alias for the translate function. While both functions have the same functionality, using __ makes our code shorter when it contains a lot of text elements to be translated.

Note

Developers should not use a variable or constant in the second parameter of the __ function. Doing so will cause problems with third-party plugins for site translation.

Making admin page code ready for translation

The previous recipe showed how to look up the translation of a text item and return its value for further processing in the plugin code. There are many instances where it is more practical to display the translated content immediately, as we'll see in this recipe.

Getting ready

You should have already followed the Adapting default user settings for translation recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch12/ch12-hello-world/ch12-hello-world-v1.php) for that recipe from the book's GitHub page and rename the file to ch12-hello-world.php.

How to do it...

Follow these steps to translate the contents of a simple administration page for immediate display:

  1. Navigate to the ch12-hello-world folder of the WordPress plugins directory of your development installation.
  2. Open the ch12-hello-world.php file in a text editor.
  3. Add the following line of code at the end of the file to register a function to be called when WordPress is building the administration page's menu:

    add_action( 'admin_menu', 'ch12hw_settings_menu' );

  4. Add the following code section to provide an implementation for the ch12hw_settings_menu function:

    function ch12hw_settings_menu() {

        add_options_page(

            __( 'Hello World', 'ch12hw_hello_world' ),

            __( 'Hello World', 'ch12hw_hello_world' ),

            'manage_options',

            'ch12hw-hello-world', 'ch12hw_config_page' );

    }

  5. Insert the following block of code to create the ch12hw_config_page function declared in the call to add_options_page:

    function ch12hw_config_page() {

        $options = get_option( 'ch12hw_options' ); ?>

        <div id="ch12hw-general" class="wrap">

        <h2><?php

            _e( 'Hello World Configuration',

                'ch12hw_hello_world' ); ?></h2>

        <form method="post" action="admin-post.php">

        <input type="hidden" name="action"

               value="save_ch12hw_options" />

        <?php wp_nonce_field( 'ch12hw' ); ?>

        <?php _e( 'Shortcode message',

                  'ch12hw_hello_world' ); ?>:

        <input type="text" name="message"

               value="<?php echo

                  esc_html( $options['message'] ); ?>"/>

        <br />

        <input type="submit" value="<?php _e( 'Submit',

                            'ch12hw_hello_world' ); ?>"

               class="button-primary"/>

        </form>

        </div>

    <?php }

  6. Add the following line of code to register a function to be executed when the administration panel is being prepared to be displayed:

    add_action( 'admin_init', 'ch12hw_admin_init' );

  7. Append the following code segment to provide an implementation for the ch12hw_admin_init function:

    function ch12hw_admin_init() {

        add_action( 'admin_post_save_ch12hw_options',

                    'process_ch12hw_options' );

    }

  8. Provide code for the process_ch12hw_options function, declared in the previous step, by inserting the following code:

    function process_ch12hw_options() {

        if ( !current_user_can( 'manage_options' ) ) {

            wp_die( 'Not allowed' );

        }

        check_admin_referer( 'ch12hw' );

        $options = get_option( 'ch12hw_options' );

        $options['message'] = sanitize_text_field(

                                  $_POST['message'] );

        update_option( 'ch12hw_options', $options );

        wp_redirect( add_query_arg( 'page',

            'ch12hw-hello-world',

            admin_url( 'options-general.php' ) ) );

        exit;

    }

  9. Save and close the plugin file.
  10. Navigate to the administration page of your development WordPress installation.
  11. Click on the Settings (Réglages in French) section on the left-hand navigation menu to expand it. Click on the new menu item labeled Hello World.

Figure 12.2 – Simple plugin administration page ready for translation

As seen in Figure 12.2, selecting the new entry displays the plugin's simple configuration form.

How it works...

This recipe makes use of the __ function, covered in the previous recipe, along with the _e function. This second function's purpose is similar to __, except that it immediately echoes the outcome of the translation lookup to the browser. It should be used for any text elements that would previously have just been simple text in HTML code or can be used to replace calls to the echo function. Of course, making a call to this function requires the presence of standard opening and closing PHP tags (<? and ?>) to be executed when placed among HTML code.

The rest of this plugin's code takes care of storing user updates in the website database, as covered previously in Chapter 3, User Settings and Administration Pages.

Modifying shortcode output for translation

As we have seen in numerous recipes, shortcodes are powerful tools that provide an easy way for users to add content to their website posts and pages. Since this content is presented to users, it can benefit from a translation just as much as the website's administration pages.

Getting ready

You should have already followed the Making admin page code ready for translation recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch12/ch12-hello-world/ch12-hello-world-v2.php) for that recipe from the book's GitHub page and rename the file to ch12-hello-world.php.

How to do it...

Follow these steps to translate shortcode output before it is displayed and learn how to deal with variable data elements that can be positioned differently between languages:

  1. Navigate to the ch12-hello-world folder of the WordPress plugin directory of your development installation.
  2. Open the ch12-hello-world.php file in a text editor.
  3. Add the following line of code at the end of the file to declare a new shortcode that will be available to content authors:

    add_shortcode( 'hello-world',

                   'ch12hw_hello_world_shortcode' );

  4. Add the following code section to provide an implementation for the ch12hw_hello_world_shortcode function:

    function ch12hw_hello_world_shortcode() {

        $options = get_option( 'ch12hw_options' );

        $output = '<p>';

        $output .=

            sprintf( __( 'The current message is: %s.',

                'ch12hw_hello_world' ),

                $options['message'] );

        $output .= '</p>';

        return $output;

    }

  5. Save and close the plugin file.
  6. Create a new page (using the Ajouter item of the Pages menu), insert the new shortcode [hello-world] in the content, and then publish the page (Publier).
  7. View the page (Voir la page) to see the output of the shortcode:

Figure 12.3 – Simple shortcode output ready for translation

How it works...

This recipe shows something that's a bit more complex than the Adapting default user settings for translation and Making admin page code ready for translation recipes. In this case, we want the shortcode output to be a combination of static text and a dynamic element. We also want that dynamic element to appear in different places based on the grammatical structure of the target language. The way to achieve this functionality is to combine the __ internationalization function with the sprintf standard PHP function.

The purpose of the sprintf function is to insert a variable in a string. It performs this task by looking for a placeholder in the target string sent in the first argument and replaces it with the variable that it receives as its second argument. Some examples of placeholders are %s for a string and %d for an integer. With this functionality in mind, we use a placeholder as part of the string to be translated so that users who create localization files can choose where the value will be placed as part of the sentence structure. Once the translation has been obtained by the __ function, we can send the alternate language string to sprintf along with the variable data to be inserted in the final string.

Translating text strings using Poedit

After inserting all the necessary code to look up translations for text elements in our plugin code, the next step is to create the actual translation files. While there are multiple tools available to perform this task, we will focus our efforts on the most popular one, the free multi-platform Poedit.

Getting ready

You should have already followed the Modifying shortcode output for translation recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch12/ch12-hello-world/ch12-hello-world-v3.php) for that recipe from the book's GitHub page and rename the file to ch12-hello-world.php.

How to do it...

Follow these steps to extract all the strings to be translated from the plugin's code using Poedit, translate them, and save the resulting language files under the plugin directory:

  1. Navigate to the ch12-hello-world folder of the WordPress plugin directory of your development installation.
  2. Create a new subdirectory named languages.
  3. Navigate to the Poedit download page and download the appropriate version of the tool for your computer (https://www.poedit.net/download).
  4. Install and start the Poedit application.
  5. Click on the New item under the application's File menu.

    Note

    It may be tempting to click on the Create new… item on the application's home page. However, this option can only be used when a translation template file (.POT) already exists, which is not our case here.

    It should also be noted that Poedit offers an automated way to create translations for WordPress themes or plugins as a paid service. We will focus on the free version of Poedit and highlight all steps required to create a translation in this mode.

  6. Select French (Canada) for Language of the translation.
  7. Click on the Save button from the toolbar and navigate to the languages subfolder created earlier in this recipe. Set the filename to ch12hw_hello_world-fr_CA.po and click on Save to save the new translation file.
  8. Click on the Translation | Properties… menu item to open the Translation Properties dialog and select the Sources paths tab.
  9. Create a new entry in the Paths list by clicking the + button under that section of the interface and selecting the Add folders… menu item.
  10. Navigate one directory up from the languages directory and click on Select Folder to select the ch12-hello-world directory. This will change the Base path field in the Sources paths tab to the selected directory and create an entry in the Paths list that simply contains the period character (.).
  11. Switch to the Sources keywords tab and add two new items to the Additional keywords list and set their values to __ and _e.
  12. Switch to the Translation properties tab and set the Project name and version field to Hello World.
  13. Click on the OK button to close the Translation properties dialog, then click on Save.
  14. Click on the Update from code toolbar button to extract all translatable items from our plugin's source code.
  15. Select the items one by one in order to display them in the lower section of the window.
  16. Enter a translation for each text element in the lower dialog box. The following screenshot shows the translations of each item to French:

Figure 12.4 – French translation of all plugin strings using Poedit

  1. Save the translation file once all strings have been translated.

How it works...

The Poedit tool searches through PHP files, looking for functions that have specific names, as specified in the Sources keywords configuration section. Based on the configuration that we specified, Poedit is able to find all the instances of the __ and _e functions in the plugin code and retrieve the text strings that are set as the first argument to these functions. Once all the strings have been found, Poedit provides a simple interface to provide translations for each string and saves the resulting translation file. Upon saving a translation project, Poedit actually creates two files, the portable object file (.po) and the machine object file (.mo). The .po file is the one we open and modify in Poedit and the .mo file is the file that WordPress uses when executing our plugin code.

The name of the language files is made up of two parts: the name of the text domain, ch12hw_hello_world, and the target language code, fr_CA. The text domain was used in all of our calls to the __ and _e functions, while fr_CA matches the language configuration that we set for our test site earlier in this chapter. To support the two other variants of the French language that WordPress supports (France French and Belgian French), we can make copies of the translation files. We can then set the proper language code in the new filenames (ch12hw_hello_world-fr_FR.po and ch12hw_hello_world-fr_BE.po) and edit them with Poedit to update each translation file's configuration.

There's more...

If you are only comfortable with English or don't want to distribute translation files with your plugins, you can, at a minimum, create a template file that users will be able to import to start their translation.

Translation template file

When you are only familiar with English, you can create a translation template that only contains the text to be translated by saving the catalog as a .pot file instead of a .po/.mo combination. In addition to the special extension, the filename should not contain a language tag (for example, ch12hw_hello_world.pot).

Loading a language file in the plugin initialization

The final step to plugin translation is to put the code in place to load a translation file. This is done by registering an action hook callback and calling a single function when it gets executed.

Getting ready

You should have already followed the Making admin page code ready for translation and Translating text strings using Poedit recipes to have the proper files required for this recipe. Alternatively, you can get the resulting code (the ch12/ch12-hello-world/ch12-hello-world-v3.php file and the ch12/ch12-hello-world/languages folder) for these recipes from the book's GitHub page. You should rename the file ch12-hello-world-v3.php to ch12-hello-world.php and copy the languages folder next to the renamed file before starting the recipe.

How to do it...

Follow these steps to load the translation file created in the previous recipe:

  1. Navigate to the ch12-hello-world folder of the WordPress plugin directory of your development installation.
  2. Open the ch12-hello-world.php file in a text editor.
  3. Add the following line of code at the end of the file to register a function to be called when the plugin is initialized:

    add_action( 'init', 'ch12hw_plugin_init' );

  4. Add the following code section to provide an implementation for the ch12hw_plugin_init function:

    function ch12hw_plugin_init() {

        load_plugin_textdomain( 'ch12hw_hello_world',

            false,

            dirname( plugin_basename( __FILE__ ) )

                . '/languages' );

    }

  5. Locate the ch12hw_set_default_options_array function in the plugin's code. Add the same call to load_plugin_textdomain at the top of the function, before the existing if statement:

    load_plugin_textdomain( 'ch12hw_hello_world', false,

        dirname( plugin_basename( __FILE__ ) )

            . '/languages' );

  6. Save and close the plugin file.
  7. Navigate to the Réglages menu to see that the plugin's menu item has changed to show its translated name (Bonjour Monde).
  8. Select the Bonjour Monde submenu item to see the translated configuration page.

  1. Use your development server's database management tool to run the following query and then Delete the resulting item:

    SELECT * FROM wp_options where option_name =

    'ch12hw_options'

  2. Go to the Extensions menu and click on the Désactiver link under the Chapter 12 – Hello World plugin to deactivate it and reactivate it by clicking on Activer.
  3. Use your development server's database management tool to run the following query. See that the message option was recreated containing a French string:

    SELECT * FROM wp_options where option_name =

How it works...

The load_plugin_textdomain function has three arguments. When called, it looks in the folder specified in the last parameter for a .mo file with a name starting with the text domain specified in the first parameter, followed by the language currently set in the WordPress configuration file. If found, the translation file is loaded in memory and is used to search for translations every time the __ or _e functions are encountered during execution. The middle argument, set to a false value, is obsolete but is still needed for backward compatibility.

Once all hooks are in place in the plugin code and a first translation file (or template) is published with the plugin, users can easily modify text elements to other languages. They can immediately start using their new translations and can also provide these new translations back to the plugin author for inclusion in future updates. We added a second call to load_plugin_textdomain in the activation hook, since the init action hook is executed later than the plugin initialization function.

There's more...

As a plugin evolves over time, new text items may need to be translated. There may also be a need to use more advanced translation functions as well as to translate JavaScript code and custom block code.

Updating a translation file

When new calls to the __ or _e functions are made in a plugin, the translation file needs to be updated to take new text elements into account. To do this, start the Poedit tool and open the existing catalog, then click on Update from code from the toolbar. This will extract all the text items and identify new entries. Once this is done, new items can be translated and saved back to the catalog file.

Advanced translation functions

While we used the most common internationalization functions in this chapter, there are a few more advanced functions that may be useful in your efforts:

  • _n( $singular, $plural, $number, $domain ): This function will look up one of the first two strings received depending on whether the $number argument is one or more.
  • _x( $text, $context, $domain ): Adds a parameter to the localization lookup to add a context parameter. This is useful when dealing with words that have the same spelling but different meanings.
  • _ex( $text, $context, $domain ): The same as _x but echoes the result of the lookup.
  • _nx( $singular, $plural, $number, $context, $domain): The same as _n with the additional context parameter from _x.

There are also a number of functions that will perform a localization lookup immediately, followed by the escaping of the resulting string. These functions include esc_attr__(), esc_attr_e(), esc_html__(), esc_html_x(), and many more. For a full list of internationalization functions, visit https://codex.wordpress.org/L10n.

Localizing JavaScript files

JavaScript files are a bit trickier to translate as they are often read from an external file that cannot contain any PHP code. The solution to this is the wp_localize_script function. When called, this function inserts a new variable that is populated with one or more localized strings in scripts that have been queued up. Upon execution, the JavaScript code will be able to access these translations and display the proper text onscreen. The following code snippet is an example showing how to use the function:

wp_enqueue_script( 'script_handle' );

$translation_vars = array( 'string_val' =>

                         __( 'Text to be translated' ) );

wp_localize_script( 'script_handle', 'javascript_object',

                    $translation_vars );  

After this code runs, a new variable array called javascript_object will be created inside the script_handle script. This object has a data member called string_val that contains a translation of the target text in the current WordPress language, if available.

Localizing custom blocks

Block editor extensions, such as the ones we created in Chapter 6, Extending the Block Editor, also need to be translated. The process to perform these translations shares some similarities with PHP-based plugin translation, but also differs in several ways that add complexity to the process.

A first step to translating blocks is to import the __ function at the top of our block source code files:

import { __ } from '@wordpress/i18n';

Once this is done, we can use this function around all text elements in our block code, similar to what we did earlier in this chapter. The following examples of the __ function come from the Creating a server-side rendering block that leverages an existing shortcode recipe in Chapter 6, Extending the Block Editor:

title: __( 'Twitter Embed', 'twitter-embed' ),

<TextControl label =

    { __( "Twitter Account User Name", 'twitter-embed' ) }

Once they have been wrapped with the __ function, all translatable strings can be extracted from the block source code and translated using Poedit, just like we did in the Translating text strings using Poedit recipe. The resulting portable object file cannot be used directly by our block and needs to be converted to a JavaScript Object Notation (.json) file. This conversion can be performed using a tool called WP-CLI, which stands for WordPress Command-Line Interface (https://wp-cli.org/), with the following command:

wp i18n make-json twitterembed-fr_CA.po --no-purge

Once the JSON version of our translations has been created, the resulting file can be renamed to twitterembed-fr_CA-ch2twe-twitter-embed.json. In this filename, the first part is the script translation domain, the second is the target translation language, and the third is the identifier of the script used when we called the wp_register_script function.

Last, but not least, you need to load the script translation and attach it to the block script code using the wp_set_script_translations function in a callback associated with the init action within your block plugin's main PHP file. The three arguments of this function are the script handle, the translation domain, and the path to the translation files:

wp_set_script_translations( 'ch2twe-twitter-embed',

    'twitterembed',

    plugin_dir_path( __FILE__ ) . 'languages' );

Once everything is in place, your custom block will appear translated when used in a page or post, as can be seen in the following figure:
