Chapter 10: Adding New Widgets to the WordPress Library

Widgets have been present in WordPress from the early days of the platform. They allow users to easily populate sidebars or other widget areas of their website theme with content that is provided by WordPress itself (post or page data) or by any plugins that have been installed (for example, book review system information). Starting with the recent version 5.8, WordPress introduced the ability to use blocks from the block editor in the widget area. That being said, the platform continued supporting legacy widgets, coded using a combination of PHP and HTML. In the subsequent version 5.9, WordPress introduced the concept of block themes, with the first example theme not supporting widgets. We can therefore say that the future of widgets is a bit uncertain, but they are still relevant to the large majority of site themes out there today.

This chapter shows how to use a widget class to create a custom content widget. It also covers the second type of widget, dashboard widgets. These can be used to display plugin-specific information on the front page of the administrative area of single-site and network WordPress installations.

In this chapter, you will learn how to create your own widget through the following topics:

  • Creating a new widget in WordPress
  • Displaying widget configuration options
  • Validating widget configuration options
  • Adding a custom dashboard widget
  • Adding a custom widget to the network dashboard

Technical requirements

You can find complete code examples on GitHub in the following repository: https://github.com/PacktPublishing/WordPress-Plugin-Development-Cookbook-Third-Edition.

Creating a new widget in WordPress

The first step in creating a custom widget is to define its name and indicate the class that contains all of its implementation functions. We also need to specify a function to render the widget's contents. Once the new element has been registered with the system, it will immediately appear in the widget list, where users will be able to drag and drop it to their widget areas.

Getting ready

You should have already followed the Updating the page title to include custom post data using plugin filters recipe in Chapter 4, The Power of Custom Post Types, to have a starting point for this recipe. Alternatively, you can get the resulting code (ch4/ch4-book-reviews/ch4-book-reviews-v12.php) from the book's GitHub page and make sure that the Chapter 4 - Book Reviews plugin is activated.

How to do it...

Follow these steps to define a new widget that displays recent book reviews from the custom post type created in Chapter 4, The Power of Custom Post Types:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Create a new directory called ch10-book-review-widget.
  3. Navigate to the directory and create a text file called ch10-book-review-widget.php.
  4. Open the new file in a code editor and add an appropriate header at the top of the plugin file, naming the plugin Chapter 10 - Book Review Widget.
  5. Add the following line of code to register a function to be called when widgets are initialized:

    add_action( 'widgets_init',

                'ch10brw_create_widgets' );

  6. Add the following code segment to provide an implementation for the ch10brw_create_widgets function:

    function ch10brw_create_widgets() {

        register_widget( 'Book_Reviews' );

    }

  7. Insert the following block of code at the end of the plugin file to declare the Book_Reviews class along with its constructor method:

    class Book_Reviews extends WP_Widget {

        function __construct () {

            parent::__construct( 'book_reviews',

                'Book Reviews',

                array( 'description' =>

                       'Displays recent book reviews' ) );

        }

    }

  8. Insert the following block of code within the Book_Reviews class, after the __construct method's closing parenthesis (}) and just before the class' final closing parenthesis (}), to define the class' widget rendering method:

    function widget( $args, $instance ) {

        extract( $args );

        $nb_reviews =

            ( isset( $instance['nb_reviews'] ) &&

            !empty( $instance['nb_reviews'] ) ?

            intval( $instance['nb_reviews'] ) : 5 );

        $widget_title =

            ( isset( $instance['widget_title'] ) &&

            !empty( $instance['widget_title'] ) ?

            esc_html( $instance['widget_title'] ) :

                         'Book Reviews' );

        $query_array =

            array( 'post_type' => 'book_reviews',

                   'post_status' => 'publish',

                   'posts_per_page' => $nb_reviews );

        $book_review_query = new WP_Query();

        $book_review_query->query( $query_array );

        echo $before_widget . $before_title;

        echo apply_filters( 'widget_title',

                            $widget_title );

        echo $after_title;

    }

  9. Continue the implementation of the widget method of the Book_Reviews class by inserting the following code at the end of the function body, right after the call to echo $after_title and before the method's closing parenthesis:

    if ( $book_review_query->have_posts() ) {

        echo '<ul>';

        while ( $book_review_query->have_posts() ) {

            $book_review_query->the_post();

            echo '<li><a href="' . get_permalink() . '">';

            echo get_the_title( get_the_ID() );

            if ( isset( $instance['show_author'] ) &&

                    'true' == $instance['show_author'] ) {

                echo ' - ' . get_post_meta(

                    get_the_ID(), 'book_author', true );

            }

            echo '</a></li>';

        }

        echo '</ul>';

    }

    wp_reset_query();

    echo $after_widget;

  10. Save and close the plugin file.
  11. Go to the Appearance section of your development site's Dashboard and Activate a theme other than Twenty Twenty-Two (such as Twenty Twenty-One or Twenty Twenty). You may need to install one of these themes if they are not present in your development environment.

    Note

    As mentioned previously, WordPress theme creation has started down a new path in version 5.9 with the introduction of block themes. The Twenty Twenty-Two theme is an example of this new theme development method and does not offer a Widgets editor, nor does it allow widgets to be added when editing the site layout. It only offers the ability to display blocks just like the ones we created in Chapter 6, Extending the Block Editor. We therefore switched to a different theme to be able to use our new widget. That being said, the majority of themes available online today do have a Widgets editor and are compatible with this recipe.

  12. Navigate to the Plugins management page and Activate the Chapter 10 - Book Review Widget plugin.
  13. Visit the Widgets menu, found in the Appearance administration menu section.
  14. Click on the + sign next to the editor title in the top-left corner and scroll down to the WIDGETS section to see the newly created Book Reviews widget. You can also search for it using the Search box.
  15. Click on the new widget to add it to the first widget section available and see it indicate that it does not have any options available. You can also click the + sign under or above existing widgets to add the Book Reviews widget to a specific location:

How it works...

The widgets_init action hook is used to register a function to be executed when widgets are being created by WordPress. When the callback occurs, we create a new widget by calling the simple register_widget function. As can be seen in the recipe, this function requires a single argument that indicates the name of a widget implementation class.

The rest of the recipe declares this widget implementation class, which extends the WordPress WP_Widget class. This initial implementation provides two essential methods to create and display a widget: the class constructor and its rendering method, the widget method. The constructor initializes the object instance by specifying a unique identifier, a title, and a description embedded within an array of optional parameters. The widget method is responsible for rendering the content of the widget. As with any other functions declared in plugins, it is important to give a unique name to the widget class and widget identifier in order to avoid conflicts with other plugins.

Similar to action hooks, which we have seen in earlier chapters, the widget method is meant to directly output HTML code. This code is displayed in the browser when an instance of the new widget has been created in a widget area.

The widget method starts by calling the standard PHP extract function on the first parameter received, an array named $args. This array contains a list of styling tidbits to render the widget. Calling the extract function parses the array and creates individual variables for each element found. This makes it easier for the following code to access the elements that should be placed before and after the widget title and widget content.

After this initial statement, the recipe continues by retrieving the number of items to display and the widget title from the $instance array. This array is received as the second parameter of the widget method. To check the values contained within the $instance array, we use a code structure that we have not seen before called a PHP ternary conditional operator (?:). This operator expects three expressions ordered as follows: (expr1)?(expr2):(expr3). Based on the values received, it returns expr2 if expr1 is true and expr3 if it's false.

Now, as we saw when we instantiated the widget, our new widget does not currently have any options. Therefore, the $instance array will actually be empty when rendering our widget for the moment. We are laying down some groundwork to be ready for the widget options that will be created in the following recipes in this chapter. This means that the default widget title (Book Reviews) and default number of reviews to display (5) will be used to display the widget.

The rest of the code is very similar to the book review shortcode created in the Displaying custom post type data in shortcodes recipe in Chapter 4, The Power of Custom Post Types. More specifically, we assemble a query parameter array that indicates the type, post status, and maximum quantity of items that we want to retrieve from the database. This query array is used to create a new instance of the WordPress WP_Query object. If results are found, the following recipe code cycles through all the entries and outputs HTML code to render an unordered list of all the items found. As part of this HTML output, the recipe formats the widget content by inserting the values of the $before_widget, $after_widget, $before_title, and $after_title variables in the right spots.

Displaying widget configuration options

Similar to plugin configuration pages, widgets can have one or more options to allow users to specify how some aspects of the component will behave. These options can be configured individually for each instance of a widget that is added to a website layout. To handle all of the logistics around multiple possible widget instances, WordPress actually takes care of most of the data handling and storage tasks.

Getting ready

You should have already followed the Creating a new widget in WordPress recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch10/ch10-book-review-widget/ch10-book-review-widget-v1.php) from the book's GitHub page and rename the file to ch10-book-review-widget.php. You should also be running the Chapter 4 - Book Reviews plugin. If needed, you can get that plugin's code (ch4/ch4-book-reviews/ch4-book-reviews-v12.php) from the book's GitHub page and Activate it.

            name="<?php echo

            $this->get_field_name( 'show_author' ); ?>">

            <option value="true"

              <?php selected( $show_author, 'true' ); ?>>

                  $this->get_field_id( 'nb_reviews' ); ?>"

How it works...

When users create a new widget instance, WordPress automatically manages configuration options for that element using an array variable. It also calls the widget class' form method to render the widget instance's options in a configuration panel.

The first few lines of code in the form method verify that the instance array contains proper values. These values should specify whether author names are to be displayed, the title that should be displayed at the top of the widget, and the number of book reviews to be shown. All of these lines use the same PHP ternary conditional operator that we just saw in the Creating a new widget in WordPress recipe.

With these variables in place, the rest of the form method's code uses a mix of HTML and PHP code to render the configuration fields that are shown in the widget editor. The get_field_id and get_field_name methods, seen throughout this code, are used to generate unique identifiers that will help WordPress to store data separately for all widget instances.

As can be seen in this recipe, the widget class is able to automatically process and save widget configuration parameters. However, it should be noted that allowing WordPress to handle this task by itself means that no validation will be performed on the data entered. This could cause problems if a user enters text instead of the number of reviews to be displayed. The next recipe shows how to handle data validation.

Validating widget configuration options

The widget configuration panel that was put in place in the previous recipe is functional and allows users to change options and save updated values in the website database. That being said, all WordPress does by default when the user saves a widget is store values directly in the site database. Accepting user data blindly is never a good idea and can lead to functionality problems and security risks if wrong or malicious values are entered. Therefore, it is preferable to add data validation rules through the creation of an update method that will be able to verify configuration data before it is saved.

Getting ready

You should have already followed the Displaying widget configuration options recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch10/ch10-book-review-widget/ch10-book-review-widget-v2.php) from the book's GitHub page and rename the file to ch10-book-review-widget.php. You should also be running the Chapter 4 - Book Reviews plugin. If needed, you can get that plugin's code (ch4/ch4-book-reviews/ch4-book-reviews-v12.php) from the book's GitHub page and Activate it.

How to do it...

Follow these steps to implement a widget's update method:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Navigate to the ch10-book-review-widget directory and edit ch10-book-review-widget.php.
  3. Find the Book_Reviews class and add the following block of code within the class after the form method's closing parenthesis (}) and before the closing class parenthesis (}) to define the update method:

    function update( $new_instance, $instance ) {

        if ( is_numeric(

                $new_instance['nb_reviews'] ) ) {

            $instance['nb_reviews'] =

                intval( $new_instance['nb_reviews'] );

        }

        $instance['widget_title'] =

            sanitize_text_field(

                $new_instance['widget_title'] );

        $instance['show_author'] =

            sanitize_text_field(

                $new_instance['show_author'] );

        return $instance;

    }    

  4. Save and close the plugin file.
  5. Visit the Widgets section of the Appearance administration menu and click on the Book Reviews widget instance to see its configuration fields.
  6. Enter a textual value (such as Test) in the Number of reviews to display field and click outside of the widget to see it again. You will see that the widget display is unchanged.
  7. Click on Update in the top right of the Widgets editor, then navigate to another page of the WordPress administration section and come back. You will see that the field's value reverts to the last valid number saved for this field.

How it works...

The update method receives two arrays of data and must return a single array to be saved in the website database. The two incoming arrays contain the new option values entered by the user and the values that were previously stored for the widget, respectively.

The method's implementation starts by using the PHP is_numeric function to check whether the value entered for the number of entries to display is a number. If it is, it calls the intval function on the incoming value to be sure it's an integer number and stores it in the array of new values for the widget. If the value received is anything but a number, it does not change the previous widget value for the number of entries. Unfortunately, it is not possible to display an error message when this type of validation of widget options is performed.

Once the numeric value has been validated, our code calls the sanitize_text_field function to remove potentially harmful HTML or PHP tags from text fields. It saves the return value in the $instance array. Once all fields have been validated, the validated $instance array is returned.

Adding a custom dashboard widget

Content widgets are used by website administrators to easily add content to their front-facing websites. WordPress contains another type of widget that plugin developers can use to enhance the administrator experience. Dashboard widgets are sections that appear on the front page of a website's administration area. These sections can offer any kind of functionality, from simple information displays indicating how much data is stored in a plugin to forms that allow website administrators to quickly perform configuration tasks.

Getting ready

You should have already followed the Updating the page title to include custom post data using plugin filters recipe in Chapter 4, The Power of Custom Post Types, to have a starting point for this recipe. Alternatively, you can get the resulting code (ch4/ch4-book-reviews/ch4-book-reviews-v12.php) from the code bundle and activate the Chapter 4 - Book Reviews plugin.

How to do it...

Follow these steps to add a new dashboard widget that indicates how many book reviews are stored in the system, along with links to quickly access them:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Create a new directory called ch10-book-review-dashboard-widget.
  3. Navigate to the directory and create a text file called ch10-book-review-dashboard-widget.php.
  4. Open the new file in a code editor and add an appropriate header at the top of the plugin file, naming the plugin Chapter 10 - Book Review Dashboard Widget.
  5. Add the following line of code to register a function to be called when the dashboard contents are being prepared:

                'ch10brdw_add_dashboard_widget' );

  6. Add the following code segment to provide an implementation for the ch10brdw_add_dashboard_widget function:

    function ch10brdw_add_dashboard_widget() {

            'book_reviews_dashboard_widget',

            'Book Reviews',

    function ch10brdw_dashboard_widget() {

            <a href="<?php echo add_query_arg( array(

            <strong>

                <?php echo $book_review_count->publish; ?>

            </strong> Published</a><br />

            <a href="<?php echo add_query_arg( array(

                'post_status' => 'draft',

                'post_type' => 'book_reviews' ),

                admin_url( 'edit.php' ) ); ?>">

            <strong>

                <?php echo $book_review_count->draft; ?>

            </strong> Draft</a>

            </div><br />

            <style>

                #book_reviews_dashboard_widget a {

                    text-decoration: none;

                }

            </style>

        <?php }

    }

  8. Save and close the plugin file.
  9. Navigate to the Plugins management page and Activate the Chapter 10 - Book Review Dashboard Widget plugin.
  10. Navigate to the website's Dashboard.

As seen in Figure 10.4, the new Book Reviews widget appears at the bottom of the page and displays information on the number of book reviews found on the site. It can be repositioned anywhere on the Dashboard.

How it works...

Any plugin can register its own dashboard widget when WordPress is putting together content for the administrative landing page. After registering a function to be called during the dashboard setup phase, our recipe makes a call to wp_add_dashboard_widget. This function allows us to register our own element for the website dashboard and provide a callback function to display its contents.

The wp_add_dashboard_widget function requires three parameters that provide a unique identifier for the new item, a title to be displayed at the top of the widget, and a function that will be responsible for generating the widget's contents. The wp_add_dashboard_widget function also has an optional fourth parameter that can be used when the widget needs to process form data as part of the dashboard widget contents.

As can be seen in the previous screenshot, dashboard widgets are displayed using WordPress meta boxes. Any HTML code echoed by the content display function directly appears in the box.

While the display function is mostly composed of HTML code, we also make a call to the wp_count_posts utility function, which easily returns the number of posts for a given post type.

The new widget can be hidden and moved to a new location on the Dashboard, like any other built-in widget. Just like the front-facing widget plugin created earlier in this chapter, it should be noted that all of the code in this plugin is in a separate file from the original book review plugin. This helps us organize our code separately from the original plugin file created in Chapter 4, The Power of Custom Post Types, and shows how developers can extend plugins they don't develop themselves.

Adding a custom widget to the network dashboard

As discussed in the Creating a network-level plugin with admin pages recipe in Chapter 3, User Settings and Administration Pages, WordPress offers a very powerful mode called network mode that allows multiple websites to be served from a single installation of the platform. When creating a plugin, developers need to think about whether it would make sense for their plugin to offer a dashboard widget that would only be seen on the network administrator's dashboard instead of being seen on individual website dashboards, or whether their plugin's scope is really more relevant at each website's level.

Getting ready

You should have already followed the Adding a custom dashboard widget recipe to have a starting point for this recipe. Alternatively, you can get the resulting code (ch10/ch10-book-review-dashboard-widget/ch10-book-review-dashboard-widget-v1.php) from the book's GitHub page and rename the file ch10-book-review-dashboard-widget.php. You should also have access to a network site configured as a network to test all of this plugin's functionality. Finally, the final version of the Chapter 4 - Book Reviews plugin should be installed and active at the network level. The Local development web server makes it easy to create a network WordPress setup.

How to do it...

Follow these steps to modify the dashboard widget defined in the previous recipe. After these modifications, it will appear in the network administration panel on network installations, while still appearing on individual site administration dashboards:

  1. Navigate to the WordPress plugins directory of your development installation.
  2. Navigate to the ch10-book-review-dashboard-widget directory and edit ch10-book-review-dashboard-widget.php.
  3. Locate the add_action call that was first added at the top of the plugin and add the following line of code right after the existing call:

    add_action( 'wp_network_dashboard_setup',

                'ch10brdw_add_dashboard_widget' );

  4. Locate the ch10brdw_dashboard_widget function and add the following code to the function around the existing implementation of the function. The new lines of code are shown in bold:

    function ch10brdw_dashboard_widget() {

        if ( is_network_admin() ) {

            $sites_list = get_sites();

        } else {

            $sites_list = array( 'blog_id' =>

                                 get_current_blog_id() );

        }

        foreach( $sites_list as $site ) {

            if ( is_network_admin() ) {

                switch_to_blog( $site->blog_id );

            }

            $site_name = get_bloginfo( 'name' );

            echo '<div>' . $site_name . '</div>';

            $book_review_count =

                wp_count_posts( 'book_reviews' );

            ?>

            // REST OF PREVIOUS EXISTING CODE

        <?php }

        }

        if ( is_network_admin() ) {

            restore_current_blog();

        }

    }

  5. Save and close the plugin file.
  6. Navigate to the website Dashboard (on a single site installation) or the network-level Dashboard (in a network installation).

Figure 10.5 – Network-level Book Reviews widget showing all sites in network

As seen in Figure 10.5, we are now able to see a new network-level widget showing all sites when we visit the network Dashboard. When viewed on a single site installation, the widget looks as it did before, with the addition of the site name.

How it works...

The initial addition made in this recipe is to associate our book review count widget code with the wp_network_dashboard_setup action hook. This makes it appear on network-level dashboard pages in addition to individual site dashboards.

Once this is done, we modify the ch10brdw_dashboard_widget function. Using the is_network_admin function, the callback determines whether it is currently running on a network-level or site-level administration page. In the case of a network-level display, our rendering code first gets a list of all sites using the get_sites function, then cycles through the list of sites. Our code then makes use of the switch_to_blog function to access data from each site's database tables. Once all the blogs have been processed, we use the restore_current_blog function to go back to the original site that is configured as the top-level site in the network.

Note

It is important to use restore_current_blog after using switch_to_blog to avoid leaving some internal variables pointing to the wrong site.

When shown on a site-level administration page or a single-site installation of WordPress, we create a dummy list of sites instead of using the get_sites function. This dummy list contains a single entry for the current site to allow us to use the same foreach loop control structure that is used at the network level. We then avoid calling the functions that are related to switching between sites when the widget is not being displayed on the network-level dashboard. Otherwise, the actual code that queries how many book reviews are present and displays them is identical between both modes of the widget output.
