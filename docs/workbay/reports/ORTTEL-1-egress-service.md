# ORTTEL-1 egress audit: description service

The default description profile is `seeded`, so the normal description request does not call a hosted LLM. Network egress is conditional for hosted OpenAI, configured GPU inference, identity and billing integrations, OCI Vault secrets, remote media URLs, operator-run evaluation, and explicit model or image/package downloads. The `runtime-vlm` image is configured offline for Hugging Face/Transformers after model seeding. The default InsightFace profile lazily constructs `FaceAnalysis`; the locked InsightFace package was unavailable here, so whether a cache miss downloads model files and which host it uses remain unverified. No Sentry, PostHog, or similar application telemetry client was found. Package telemetry is only partly verified below.

## Recommended switches and placement

- **Dockerfile `runtime-base`:** `ORT_DISABLE_TELEMETRY=1` is set for both serving stages as defense-in-depth. Set `HF_HUB_DISABLE_TELEMETRY=1` here as an explicit guard; retain the existing offline flags in `runtime-vlm`.
- **Compose or systemd environment:** keep `ACX_DESCRIPTION_ADAPTER=seeded` (or an approved local profile), do not set `ACX_HOSTED_PROVIDER_OPTIN=1`, and keep GPU inference URLs private and allowlisted. Use `RECOGNITION_SECRET_BACKEND=env` unless Vault access is intended.
- **Serving network policy:** allow only required database, in-tenancy inference, and approved media hosts. Prestage InsightFace/HF/model assets before runtime; the `runtime-vlm` image already uses `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1`.
- **Build/evaluation environment:** use an internal package/image mirror for Docker/uv/apt builds. Keep live evaluation variables and commands out of production service units.

## Gaps

- The sandbox has no service-local `.venv`. The lane test environment contains `huggingface-hub==0.36.2`, matching the lock, but ONNX Runtime in that environment is 1.29.0 rather than the service image's 1.28.0 from `apps/prototype-description-service/uv.lock`; SQLAlchemy, Alembic, and OCI SDK versions also differ from their selected lock entries. `transformers`, `torch`, and `insightface` are absent. Package-native telemetry defaults and exact opt-outs remain unverified for the locked ONNX Runtime 1.28.0, Transformers 4.48.3, Torch 2.13.0+cpu, InsightFace 0.7.3, SQLAlchemy 2.0.49, Alembic 1.18.4, FastAPI 0.129.2, and Uvicorn 0.39.0 because their exact locked sources were unavailable. OpenCV's Python wrapper was searched, but its native binary was not audited.
- Locked InsightFace 0.7.3 source is unavailable, so its cache-miss model-download host/behavior is unverified. Verify it from that exact source or preseed the model cache and enforce an outbound allowlist.
- The [ONNX Runtime Privacy v1.28.0](https://github.com/microsoft/onnxruntime/blob/v1.28.0/docs/Privacy.md) note says telemetry was implemented only for Windows builds, so active telemetry is not confirmed on the Linux runtime image. `ORT_DISABLE_TELEMETRY=1` is set in Dockerfile `runtime-base` as defense-in-depth; the collector host and event fields were not verified from the locked source.
- No external CDN/font URL or application error-reporting/analytics SDK was found in the inspected service tree. OpenCV's native binary and telemetry behavior for the missing optional dependency sources were not exhaustively inspected.
