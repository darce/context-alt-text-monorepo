## 5. Risks / gotchas for the lanes

- **`GuidedUxMap.contract.test.ts` asserts against the JSON map directly** (`docs/ux-maps/guided-prototype.uxmap.json` per §2 MAINT-GP-DOCS-20260905) — screen ids and one-action-per-person shape are load-bearing; a copy/catalog change that adds/renames a screen or a second per-person action will fail this contract test even if the UI itself looks fine.
- **`liveDescription.ts` reason vocabulary is centralized** (`GUIDED_LIVE_REASON`, `GUIDED_LIVE_BLOCKED_REASON`, `DESCRIBE_*`) per GUIDEDFIX-1 decision 9151 — adding a new terminal/blocked state must extend these enums, not add a parallel string literal; multiple historical findings (12002, 12008, 12013-15) were exactly this class of drift between code and ux-map doc.
- **gpu_state vs tier**: never let a `gpu_state` label override tier-derived ready/degraded classification (GUIDEDGPU-1 decision 9108; also enforced by `liveDescription.test.ts:170` and `:670`). Any new "which run is still being paid for" logic must stay consistent with the existing "counts every waiting phase, times out counts, nothing before server names a run" rules (`liveDescription.test.ts:368-410`).
- **Deadline only ever widens, never shrinks** — this is asserted in at least 3 places (`liveDescription.test.ts:411-442`, `:854-928`, `useGuidedLiveDescription.test.tsx:505`); any lane touching deadline/ceiling math must preserve monotonicity.
- **Focus contract on guide open/close/undo** is a repeat regression class (GUIDED-PROTOTYPE-1 findings 11556, 11570, 11572) — guide-open must focus the non-interactive status target (`tabIndex=-1`), End-guide must restore focus, and Undo's step/focus must agree; `GuidedPrototypePage.test.tsx` has explicit focus-restoration tests (lines 99, 158, 418) that will catch regressions but only if a new lane doesn't skip re-running that file.
- **Live demo against prod is currently broken** (MAINT-demo-qm-20260907 blocker 460, decision 9268/9269 — prod stack drift, not app code) — do not treat a live-panel manual smoke test against `demo.altcontext.com` as meaningful signal for these lanes; rely on the mocked hook/component suites.
- **Peer-coordination lock**: EVID-1 decision 9368 explicitly names this exact worktree (`context-alt-text-monorepo-guidedqm-1`, branch `feature/guidedqm-1`) and forbids shared-main merges without coordinating with the Codex peer session first — check for a fresher coordination decision before merging, and do not touch the two backend/deploy paths that decision reserved to the peer side (`scripts/deploy/recognition-service.sh`, `001_identity_schema.py`, `docker-entrypoint.sh`).
- **Lane manifests are non-authoritative for scope**: `owned_paths`/`non_goals` in `DEMOUX-W0A/B.json` and `DEMOLIVE-9.json` are empty template placeholders (see §3) — do not rely on them to infer which files a lane is allowed to touch; use the handoff decisions and this packet's §2 instead.
- **`GuidedFaceMatchCard`**: disabling logic distinguishes "both answers disabled + described" (unsaved edit present) vs "only the matching answer disabled" (no unsaved edit) — a copy/catalog change that reworks the edit-vs-decision interaction must keep this distinction or it breaks `GuidedFaceMatchCard.test.tsx:182,196`.
