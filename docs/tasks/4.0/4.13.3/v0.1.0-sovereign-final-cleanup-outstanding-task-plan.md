# 4.13.3 -- v0.1.0 Sovereign Final Cleanup: Outstanding and Deferred Closure

## Problem Statement

The primary cleanup slice closed high-priority implementation defects, but several documented items remain open across docs, contracts, release workflow, stretch evaluations, and post-v0.1.0 deferred architecture. These open items currently live in multiple sections of the cleanup plan and need one executable plan of record. This task consolidates and closes all non-testing outstanding work.

## Workflow Principles

- Keep the sovereign model authoritative: local projection remains the runtime source of truth.
- Resolve checklist drift by linking each open item to a concrete file edit or explicit defer decision.
- Exclude automated and manual test execution steps from this plan; testing is run manually at the end of the slice.

## Terminology

- **Closeout item**: A remaining v0.1.0 task required for documentation, contracts, or release completion.
- **Stretch item**: A non-blocking improvement that may be implemented now or explicitly deferred with rationale.
- **Deferred item**: A post-v0.1.0 capability that requires separate scoped execution plans.

## Current State Analysis

- Cleanup findings `H-cleanup-1`, `H-cleanup-2`, and `H-cleanup-3` are fixed and verified in code.
- Closeout artifacts are now present: contract finalized, shared schema added, sovereign data-flow diagram added, and `v0.1.0` tag created.
- Stretch decisions are documented in `v0.1.0-stretch-decisions.md` (`acx://` keep, naming deferred, snapshot polish scoped).
- Deferred architecture items are now linked to child plans in the epic (`v0.2` outbox, Action Scheduler, delta ingest, drift reconciliation).

## Proposed Solution

Execute a single reconciliation slice in three phases: v0.1.0 closeout artifacts, stretch-goal disposition, and deferred-item activation into explicit follow-on task plans. The slice completes when each currently open item is either implemented or reclassified to an explicit deferred plan with owner and dependency notes.

## Patterns to Follow

### Contract to Schema Synchronization

```md
1. Update canonical contract in docs/agentic/contracts/.
2. Mirror the response shape in packages/shared-contracts/schemas/.
3. Link schema artifact in packages/shared-contracts/README.md.
4. Record completion in the originating task checklist.
```

### Explicit Defer with Child Plan

```md
- [ ] Deferred capability remains open in epic
  -> Create child task plan with:
     - scope boundary
     - dependency owner
     - exit criteria
     - target milestone
```
