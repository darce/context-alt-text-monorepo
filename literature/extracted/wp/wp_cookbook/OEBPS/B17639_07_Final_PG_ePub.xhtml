Chapter 7: Accepting User Content Submissions

Giving users the ability to contribute content to a website is always a good way to engage the community and keep content fresh on a website. That being said, WordPress does not provide any built-in mechanism for site visitors to submit content to site administrators. This is even more obvious when you consider that adding a simple contact form to a site requires the installation of a plugin.

Going back to the book review system that was put in place in Chapter 4, The Power of Custom Post Types, this chapter will show you how to create a user-facing form to allow visitors to submit their own book reviews to a website. We'll also see how to save this information in the site database, send out email notifications, and implement spam protection through the following recipes:

  • Creating a client-side content submission form
  • Saving user-submitted content in custom post types
  • Sending email notifications upon new submissions
  • Implementing a CAPTCHA on user forms using an online service
  • Using a local library to implement a CAPTCHA on user forms

Technical requirements

Creating a client-side content submission form

The first step toward giving visitors the ability to contribute to a website is to present a form that they can use to submit new content. This recipe shows how to create a shortcode that can easily be inserted on any WordPress page to render a simple form.

How it works...

As seen in the previous chapters, shortcodes are special blocks of text that can be easily added to any post or page to be replaced by content when they are found in pages visited by users. This recipe uses the add_shortcode function to declare a new shortcode, [submit-book-review]. The shortcode gets replaced with a review submission form when placed on a post or page. Of course, you could also try making a block out of it, as seen in the Creating a server-side rendering block that leverages an existing shortcode recipe in Chapter 6, Extending the Block Editor.

The form itself is created using standard HTML and displays a number of text fields. It also uses a bit of PHP code to dynamically build the list of ratings and book types defined in the system. The form includes a call to the wp_nonce_field function, which was previously seen when creating plugin configuration panels. This function adds hidden fields that will be used as a security measure in the associated data processing function. Finally, the code checks to see whether the user visiting the page is logged in to the website. In the case of a negative result, it displays a short message instead of the submission form.

When submitted, the action associated with the form sends visitor-provided content to the page where the book review form is displayed. This new content will be intercepted and processed in the code that will be added in the next recipe.

Finally, the ob_start, ob_get_contents and ob_end_clean functions are standard PHP functions that allow us to capture any output that would normally be sent to the browser, as well as have access to this output buffer before clearing it out. By using these functions, we are able to simplify the way we implement our shortcode function instead of having to append all of the form's HTML code to a content variable.

Note

Placing it in a separate file helps us start with a clean slate and also shows us that one plugin can augment another plugin's functionality. If you search for Contact Form 7 or Elementor on the official WordPress plugin repository, you'll see that many developers have found ways to extend these popular plugins.

Saving user-submitted content in custom post types

When visitors click on the Submit Review button on the form created in the previous recipe, the target of the form is set to be the page that is hosting the submission form. Since this page is not capable of handling form data, we must implement an action hook that intercepts this post data and sends it to a processing function that we will define before returning visitors to the submission form page.

Getting ready

You should be running the final version of the Chapter 4 - Book Reviews plugin created in Chapter 4, The Power of Custom Post Types, and should have already followed the Creating a client-side content submission form recipe. Alternatively, you can get the files from the book's GitHub page (ch4/ch4-book-reviews/ch4-book-reviews-v12.php and ch7/ch7-book-review-user-submission/ch7-book-review-user-submission-v1.php) and rename ch7-book-review-user-submission-v1.php to ch7-book-review-user-submission.php.

How to do it...

Follow these steps to implement a function responsible for processing user input for the review submission form:

  1. Navigate to the ch7-book-review-user-submission directory of the WordPress plugins folder of your development installation.
  2. Open the ch7-book-review-user-submission.php file in a text editor.
  3. Add the following line of code to register a function that will intercept user-submitted book reviews:

    add_action( 'template_redirect',

                'ch7_brus_match_new_book_reviews' );

  4. Add the following block of code to implement the ch7_brus_match_new_book_reviews function:

    function ch7_brus_match_new_book_reviews( $template ) {

        if ( !empty(

                $_POST['ch7_brus_user_book_review'] ) ) {

            ch7_brus_process_user_book_reviews();

        } else {

            return $template;

        }

    }

  5. Insert the following code to provide an implementation for the ch7_brus_process_user_book_reviews function:

    function ch7_brus_process_user_book_reviews() {

        // Check all required fields present and non-empty

        if ( !wp_verify_nonce( $_POST['br_user_form'],

                               'add_review_form' ) ||

              empty( $_POST['book_title'] ) ||

              empty( $_POST['book_author'] ) ||

              empty( $_POST['book_review_text'] ) ||

              empty( $_POST['book_review_book_type'] ) ||

              empty( $_POST['book_review_rating'] ) ) {

            $abort_message = 'Some fields were left ';

            $abort_message .= 'empty. Please go back ';

            $abort_message .= 'and complete form.';

            wp_die( $abort_message );

            exit;

        }

        $new_br_data = array( 'post_status' => 'publish',

            'post_title' => sanitize_text_field(

                                $_POST['book_title'] ),

            'post_type' => 'book_reviews',

            'post_content' => sanitize_text_field(

                         $_POST['book_review_text'] ) );

        // Store ID from post insertion

        $new_book_review_id =

            wp_insert_post( $new_br_data );

        add_post_meta( $new_book_review_id, 'book_author',

            sanitize_text_field(

                $_POST['book_author'] ) );

        add_post_meta( $new_book_review_id, 'book_rating',

            (int) $_POST['book_review_rating'] );

        $type = sanitize_text_field(

                    $_POST['book_review_book_type'] );

        if ( term_exists( $type,

                'book_reviews_book_type' ) ) {

            wp_set_post_terms( $new_book_review_id,

                               $type,

                               'book_reviews_book_type' );

        }

        $redirect_address =

            ( empty( $_POST['_wp_http_referer'] ) ?

            site_url() : $_POST['_wp_http_referer'] );

        wp_redirect( add_query_arg( 'add_review_message',

                         '1', $redirect_address ) );

        exit;

    }

  6. In the original ch7_brus_book_review_form function, add the following code shown in bold between the wp_nonce_field function call and the opening table tag:

    <?php wp_nonce_field( 'add_review_form',

                          'br_user_form' ); ?>

        && $_GET['add_review_message'] == 1 ) { ?>

    <div style="margin: 8px;border: 1px solid #ddd;

        background-color: #ff0;">

    Thank for your submission!</div>

    <?php } ?>

    <!-- Variable to indicate user-submitted items -->

    <input type="hidden" name="ch7_brus_user_book_review"

           value="1" />

    <table style="width:100%"><tr>

  8. Go back to the page containing the book review submission form and refresh the page to have the latest version of the form code.
  9. Complete all fields and click on Submit Review to send all the fields to the newly created processing function. After processing the new content, the script will return to the form and display a confirmation message.
  10. Visit the Book Reviews section of your site's administration pages to see your newly submitted entry.

How it works...

The purpose of this recipe is to process the book review data submitted by users with the form created in the previous recipe. In the first few steps, we assign a function to the template_redirect action hook to allow us to capture this data. This hook function is executed very early in the WordPress processing sequence. If a specific POST variable is found, we call our processing function that is defined in the rest of the recipe. Otherwise, we let WordPress process the page request normally.

The first thing that is done in our processing function is to check whether the proper hidden data field is found as part of the post data, using the wp_verify_nonce function. If it is not present, it indicates that someone may be trying to send data to the website without having visited the frontend form. In this case, our code displays an error message using the wp_die function. We also check whether all the form fields are non-empty, displaying the same error message if any field does not contain a value.

Once we are sure that all input is present and the posted data is valid, the next steps place all received data in an array. This data includes the book's title and review text, along with a post status and the book_reviews post type name. The resulting array is sent to the wp_insert_post function to create a book review and store the information within. As we can see, wp_insert_post only requires a single parameter, which receives the array that we just created. While we only define four elements in that data array, many more are available, as can be seen by consulting the WordPress Code Reference (https://developer.wordpress.org/reference/functions/wp_insert_post/).

Now, calling wp_insert_post only takes care of storing some key data elements that belong in the post data. We must follow up this code with calls to update_post_meta and wp_set_post_terms to store the remaining book review information in the website database.

Once all the information is stored, we use a combination of the wp_redirect and add_query_arg functions to send the user back to the page where they submitted their book review. Our code also makes sure that only one instance of the add_review_message variable is in the target address.

Finally, this recipe makes a small modification to the book review form to add a confirmation message shown to visitors when information is accepted by the plugin.

Sending email notifications upon new submissions

Just like WordPress sends out email notifications to the administrator when new comments are posted, it can be very useful to send out emails when visitors post new book reviews. This allows website managers to review new content as it comes in and decide whether they approve it to be published online.

Getting ready

You should be running the final version of the Book Reviews plugin created in Chapter 4, The Power of Custom Post Types, and should have already followed the Saving user-submitted data in custom post types recipe (including changing the post status to draft as indicated in the There's more... section). Alternatively, you can get the resulting files from the book's GitHub page (ch4/ch4-book-reviews/ch4-book-reviews-v12.php and ch7/ch7-book-review-user-submission/ch7-book-review-user-submission-v2.php) and rename ch7-book-review-user-submission-v2.php to ch7-book-review-user-submission.php. Finally, you should have access to a WordPress installation on a hosted web server, as emails are usually not sent when running it on a local installation. Be sure to have access to the email account associated with the site administrator account to see the resulting email.

If you're using Local as your development server, you can go to the TOOLS tab of your site configuration and click on OPEN MAILHOG to capture emails. Once the MailHog page appears in your browser, click on Connected and use the Refresh button (button with two spinning arrows) to see captured emails after completing this recipe.

How to do it...

Follow these steps to add code that will prepare email data for new reviews and send it using the wp_mail function:

  1. Navigate to the ch7-book-review-user-submission directory of the WordPress plugins folder of your development installation.
  2. Open the ch7-book-review-user-submission.php file in a text editor.
  3. Add this following code at the end of the plugin file to define a new filter function to set the sending email address when using the wp_mail function:

    function ch7_brus_custom_wp_mail_from( $orig_email ) {

        return str_replace( 'wordpress@', 'bookreviews@',

                            $orig_email );

    }

  4. Add the following block of code at the end of the plugin file to define a second filter function to define the name of the sender when using the wp_mail function:

    function ch7_brus_custom_wp_mail_from_name( $from ) {

        return get_bloginfo( 'name' ) . ' - ' .

            'Book Review System';

    }

  5. Insert the following line of code to register a function to be called back when new posts are submitted:

    add_action( 'wp_insert_post', 'ch7_brus_send_email',

                10, 2 );

  6. Insert the following block of code to implement the ch7_brus_send_email function:

    function ch7_brus_send_email( $post_id, $post ) {

        if ( !isset(

                $_POST['ch7_brus_user_book_review'] ) ||

                'book_reviews' != $post->post_type ) {

            return;

        }

        $admin_mail = get_option( 'admin_email' );

        $headers = 'Content-type: text/html';

        $message = 'New user book review.<br />';

        $message .= 'Book Title: ';

        $message .= esc_html( $post->post_title );

        $message .= '<br /><a href="';

        $message .= add_query_arg( array(

                        'post_status' => 'draft',

                        'post_type' => 'book_reviews' ),

                        admin_url( 'edit.php' ) );

        $message .= '">Moderate new book reviews</a>';

        $email_title = "Book Reviews - ";

        $email_title .= esc_html( $_POST['book_title'] );

        add_filter( 'wp_mail_from',

                    'ch7_brus_custom_wp_mail_from' );

        add_filter( 'wp_mail_from_name',

                    'ch7_brus_custom_wp_mail_from_name' );

        wp_mail( $admin_mail, $email_title, $message,

                 $headers );

        remove_filter( 'wp_mail_from',

                       'ch7_brus_custom_wp_mail_from' );

        remove_filter( 'wp_mail_from_name',

            'ch7_brus_custom_wp_mail_from_name' );

    }

  7. Save and close the plugin file.
  8. Go back and visit the book review submission form and submit a book review.

How it works...

The wp_mail function can be used by any plugin to send out email messages. It takes five arguments to define all the elements of the outgoing message:

wp_mail( $destination, $subject, $message, [$headers],

         [$attachments] );

The first three arguments are required and define, respectively, the email address of the intended recipient, the title of the message, and its content. As we have seen in this recipe, the content is mainly specified using standard HTML syntax, while the target email address is retrieved from the site options table using the get_option function. As for the title, it is built from static text and the book review title to create the final result.

The next parameter is optional and provides header information for the email, with the most important piece of information in that section being the character set. The last parameter can optionally be used to specify the path of one or more files to be sent as email attachments.

To make it easier for website administrators to manage new entries, part of the message body contains a link to the book reviews management page of the WordPress website administration area to quickly display all the unapproved entries (set as draft items).

The recipe also makes use of the wp_mail_from and wp_mail_from_name filters to change the email address and sender name when calling the wp_mail function. These filters are registered just before calling wp_mail and removed right after the function call to avoid affecting other calls to wp_mail in WordPress or other plugins.

Implementing a CAPTCHA on user forms using an online service

A common security measure on website forms is to use CAPTCHA codes. These codes use distorted letters or some other form of test to check that the person submitting data is not a spam robot. The form that we have been building to accept visitor-submitted book reviews could benefit from this type of technology to avoid weeding through unwanted entries.

This recipe shows how to integrate Google's reCAPTCHA service in our book review submission form. If you prefer using a local CAPTCHA script to avoid being dependent on an online service or to be sure that your form can be used around the globe, jump to the next recipe, Using a local library to implement a CAPTCHA on user forms.

Getting ready

You should be running the final version of the Book Reviews plugin created in Chapter 4, The Power of Custom Post Types, and should have already followed the Sending email notifications upon new submissions recipe. Alternatively, you can get the resulting files from the book's GitHub page (ch4/ch4-book-reviews/ch4-book-reviews-v12.php and ch7/ch7-book-review-user-submission/ch7-book-review-user-submission-v3.php) and rename ch7-book-review-user-submission-v3.php to ch7-book-review-user-submission.php before starting the recipe. How it works...

Google's reCAPTCHA service is a free service that can generate and display a CAPTCHA box in your form. It has evolved over time from asking users to decipher a scrambled message in an image to displaying addresses and other street signs. Other versions asked users to enter what they saw. In its latest incarnation, reCAPTCHA simply asks the user to check a box to indicate that they are not a robot. If it suspects the visitor might be an automated system, then it asks more advanced questions. When visitors check the box, a hidden field is populated with a validation code that gets sent to our data processing function along with the rest of the form data.

Adding a reCAPTCHA to our form is actually quite easy. It only requires us to load a JavaScript file and add a line of code to our form that gets transformed into the service's trademark checkbox. Once the form data is posted, validating it is a bit more complex than the nonces we have used before. More specifically, our plugin needs to communicate with Google's servers to check the validation code. Thankfully, Google offers an easy-to-use library to hide away much of this operation's complexity. If the reCAPTCHA code received is valid, the previously created data processing and storage code is executed as before. Otherwise, an error message is displayed to users. In addition to being easy to integrate, a benefit of using a third-party service is that most code updates are done by the service provider. You would still need to check for occasional updates to the PHP validation library, but that is only a small part of this service's functionality.

If you are planning to distribute a plugin that makes use of the reCAPTCHA service, it would not make sense to leave your own website and secret keys in the final plugin code. You should instead create an administration panel, as we learned to do in Chapter 3, User Settings and Administration Pages. This way, users can enter their own keys and have them be used on the website.

Note

It should be noted that while Google reCAPTCHA is one of the most popular CAPTCHA generation services, it does not directly work in China at the time of writing. It has not worked there for some time and might also be blocked by other countries. If you are developing a plugin for a wide audience, you might want to consider supporting more than one CAPTCHA service or library. This way, your users will have options, no matter where they or their audience resides. Read the next recipe for an example of using a local library to generate a CAPTCHA.

Using a local library to implement a CAPTCHA on user forms

As discussed in the previous recipe, Implementing a CAPTCHA on user forms using an online service, adding a CAPTCHA to visitor-facing forms helps reduce unwanted submissions to a website. After seeing how to integrate an online third-party service, this recipe shows how to download and integrate a local PHP script to generate and validate CAPTCHA images locally.

Getting ready

You should be running the final version of the Book Reviews plugin created in Chapter 4, The Power of Custom Post Types. You should also have already followed the Sending email notifications upon new submissions recipe. You should not have any Google reCAPTCHA code from the previous recipe.

Alternatively, you can get the resulting files from the book's GitHub page (ch4/ch4-book-reviews/ch4-book-reviews-v12.php and ch7/ch7-book-review-user-submission/ch7-book-review-user-submission-v3.php). The ch7-book-review-user-submission-v3.php file should be renamed to ch7-book-review-user-submission.php before starting the recipe.

The GD and FreeType PHP libraries need to be installed and activated in your development web server's PHP installation to be able to generate a CAPTCHA image. Most of the pre-packaged local web servers listed in the Installing a web server on your computer recipe from Chapter 1, Preparing a Local Development Environment, come with these libraries activated. They are also commonly enabled on most hosted web servers. That being said, you should still mention that they are required when distributing a plugin containing the following code to a larger audience.

How it works...

The Securimage script is a simple tool that can generate and display a CAPTCHA image, as well as store the string that it generated using session data.

The recipe's code displays the CAPTCHA image by using a standard HTML img tag that uses one of the scripts in the securimage directory as the image path. On the data processing side, our code first starts by calling session_start to reconnect to the session that was initiated by the image generator to store the CAPTCHA code. It then proceeds to check whether the user CAPTCHA text matches the image that was displayed using the check method of the securimage class. Based on this result, we display an error message or continue verifying that the rest of the required data fields have been submitted correctly.

While there are many PHP scripts available for generating CAPTCHA images, this particular one was selected for this recipe since it uses the BSD license. This makes it compatible with WordPress licensing. You would therefore be able to distribute this script with your plugin on the official WordPress plugin repository.
