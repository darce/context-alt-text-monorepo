## HIGH Severity (Fixed)

### H-1 · SnapshotClient endpoint path missing `/recognition` prefix

|              |                                                                   |
| ------------ | ----------------------------------------------------------------- |
| **Files**    | `src/sovereign/sync/class-snapshot-client.php` L69                |
| **Category** | GAP                                                               |

`SnapshotClient::get_snapshot_endpoint_path()` returned `/tenants/%s/clusters/snapshot` as the default path. The Python backend mounts the clusters router under `/recognition`, so the full endpoint path is `/recognition/tenants/{tenant_uuid}/clusters/snapshot`. The missing prefix caused every `fetch_snapshot()` call to hit a 404, meaning **bootstrap sync always failed** and local projection tables were never populated. Without populated local tables, the projection gate remained `false` and the plugin always fell through to the proxy path — which returns nothing when the service is down.

**Fix:** Changed default path to `/recognition/tenants/%s/clusters/snapshot`. Test updated to verify the prefix.

### H-2 · Offline response envelope mismatch — frontend receives object instead of array

|              |                                                                   |
| ------------ | ----------------------------------------------------------------- |
| **Files**    | `src/api/class-clusters-controller.php` L138–144, L175–179       |
| **Category** | GAP                                                               |

`list_clusters()` and `list_top_unlabeled_clusters()` offline paths wrapped the cluster array in `{ clusters: [...], tenant_id: "..." }`. The Python backend returns a bare `list[ClusterResponse]` array and the frontend calls `fetchRequiredApi<ClusterSummary[]>()` which casts the raw JSON directly — no envelope unwrapping. When the offline path was active, the frontend received an object instead of an array, causing `clustersQuery.data` to be the wrapper object. Array methods (`.map()`, `.length`, etc.) silently failed, displaying zero clusters with no console errors.

**Fix:** Both offline paths now return the bare array directly: `new WP_REST_Response($clusters, 200)`. Tests updated with `assertArrayNotHasKey('clusters', $data)` guards to prevent regression.

## MEDIUM Severity

### M-1 · `ReflectionProperty::setAccessible()` deprecated in PHP 8.5

|              |                                                                   |
| ------------ | ----------------------------------------------------------------- |
| **Files**    | `tests/Unit/RecognitionControllerTest.php` L60, L64, L69, L74, L79 |
| **Category** | ANTIPATTERN                                                       |

`testDefaultCompositionWiresSyncJobAndSharedSyncStateRepository` calls `setAccessible(true)` on 5 `ReflectionProperty` instances. This method is a no-op since PHP 8.1 and triggers deprecation notices on PHP 8.5+. Removing the 5 `setAccessible(true)` calls silences the warnings without behavioral change.

**Impact:** Test-only. No runtime effect. PHPUnit reports 5 deprecation notices.

### M-2 · `RecognitionController` composition has fragile conditional branching

|              |                                                                  |
| ------------ | ---------------------------------------------------------------- |
| **Files**    | `src/api/class-recognition-controller.php` L52–72                |
| **Category** | COMPLEXITY                                                       |

The default composition path in `register_routes()` builds 6 shared objects and passes them through a `null !== $clusters_controller` guard. This conditional exists because `ClustersController` construction can fail (e.g., missing table). If it fails, `ClusterMutationsController` is also skipped, which means mutation routes are silently unregistered. There is no logging or error reporting when this happens.

**Impact:** Silent failure mode. If table creation fails, users get 404s on mutation endpoints with no diagnostic trail. Acceptable for prototype phase but should be addressed before production.

## New Bugs Found

1. **H-1 (fixed)** — `SnapshotClient` default endpoint path `/tenants/%s/clusters/snapshot` was missing the `/recognition` prefix. Bootstrap sync always returned 404, preventing local table population. Fixed to `/recognition/tenants/%s/clusters/snapshot`.
2. **H-2 (fixed)** — Offline `list_clusters()` and `list_top_unlabeled_clusters()` wrapped results in `{ clusters: [...], tenant_id }` envelope. Frontend expects a bare `ClusterSummary[]` array. Envelope removed.
3. **H-3 (fixed)** — `useSyncTrigger` hook fired a single `mutation.mutate()` on mount, but the `useEffect` deps `[isStale, lastSyncedAt]` never changed again (`[true, null]` stays constant). After the initial attempt, `mutation.isSuccess` became `true` (HTTP 200 even on `synced: false`), blocking further attempts. The 3-retry backoff timer used a stale `mutation` ref in its `useCallback([], [])` closure and exhausted after ~3.5 min. If the description service was down during that window, the plugin never synced — even after the service came online. Fixed: switched from one-shot effect + limited retries to persistent `setInterval` polling (30 s) that re-attempts `mutation.mutate()` while `isStale && !lastSyncedAt` holds, guarded by an `isPendingRef` to prevent overlapping calls. Interval is cleared on success or unmount. Added "Waiting for service… / Retrying" UI state for in-between-polls feedback.

## LocalWP Database Audit

To inspect the local plugin tables in a LocalWP site, use the helper script from the monorepo root:

```bash
# Auto-discovers the LocalWP MySQL socket and connects
scripts/localwp-db.sh -e "SELECT * FROM wp_acx_sync_state;"
scripts/localwp-db.sh -e "SELECT COUNT(*) AS n FROM wp_acx_clusters;"
scripts/localwp-db.sh -e "SELECT COUNT(*) AS n FROM wp_acx_identity_members;"

# Interactive session
scripts/localwp-db.sh
```

The socket path is volatile (contains a per-site hash). The script searches
`~/Library/Application Support/Local/run/` for `mysqld.sock` automatically.
Override with environment variables if needed:

```bash
LOCALWP_SOCKET=/path/to/mysqld.sock scripts/localwp-db.sh -e "SHOW TABLES LIKE '%acx%';"
```
