## Problem Statement

FIR-3 landed parity-proven adapters that nothing constructs at runtime. The runtime has three symmetric construction sites (`scan_worker._ensure_embedding_runtime`, `tasks/scan.py`, HTTP `deps/services.py get_scan_service_builder`) that hardwire InsightFace with no backend-selector setting — swapping backends today means editing glue at every site ([SERVE-01]). The FIR-3 adapters also do not implement the FIR-2 protocols (numpy-BGR batch I/O + `RawDetection` vs `Iterable[bytes|str]` → `FaceDetection`), so a bridge is required: it reuses FIR-3's adapters/aligner verbatim and adds exactly one new transform — bytes→BGR decode, pinned to incumbent semantics by a golden fixture ([SERVE-08]). Meanwhile `check_model_cache` only counts `.onnx` files; a corrupted or swapped model passes /ready ([EMB-05], [DRIFT-02]).

## Constraints

- **Dark by construction**: production default = incumbent. The flag is the only entry to the new path; both branches of the flag are tested live matrix, and the flag inventory is explicit — one flag, documented, removed at FIR-6 switch-over or FIR-8 abandonment ([SERVE-03], [RLSE-07]).
- **One embedding space per comparison** ([EMB-01]): the face_pipeline path emits 128D under a space-token stamped manifest (FIR-4-era bare `opencv-sface@128d/l2/cosine`; **superseded by CVUP-1** — live stamp is `opencv-sface+{space_token}@128d/l2/cosine`, e.g. `opencv-sface+cv5.0.0/ort1.28@128d/l2/cosine`); incumbent rows are 512D `insightface-buffalo_l@512d/l2/cosine`. **`PGVECTOR_DIM` is the sole dimension root** (`db/settings.py` → `pgvector_dimension` feeding the `Vector` column). `identity_detection.embedding_dimension` is derived from that root (not a second knob); `RECOGNITION_EMBEDDING_DIMENSION` is ignored/removed. When the flag selects face_pipeline, the shared factory asserts **three-way equality** `manifest.dimensions == pgvector_dimension == identity_detection.embedding_dimension` at construction and fails closed on mismatch (`Unavailable*` with reason, surfaced via the profile-aware readiness check). Dark 128D sets `PGVECTOR_DIM=128` and requires a fresh DB (greenfield `001_identity_schema.py` derives `EMBEDDING_DIMENSION` from settings/`PGVECTOR_DIM`; defaults flip only in FIR-6). Live readiness verifies Vector typmods against the configured width. Mixed-dimension writes are additionally rejected loudly by the fixed-width pgvector column, and S4's `_persist_identities` change adds a one-line application-level assert `len(det.embedding) == pgvector_dimension` with a clear `ValueError` — defense in depth so a non-factory construction path surfaces cleanly instead of as an opaque DB error ([PROV-08], [DRIFT-02]). Rows always stamp `embedding_model` ([PROV-01], [PROV-06]); the existing NOT-NULL + `ValueError` guard in `ScanService` stays load-bearing.
- **Fail closed, loudly**: model file missing / sha256 mismatch / license-hash mismatch → `UnavailableFaceDetector`/`UnavailableEmbeddingGenerator` with a recorded reason + UNHEALTHY /ready, never a silent stub fallback in production mode ([RLSE-05], [AGT-10]). Stub remains test-mode-only, as today.
- **Transform parity**: the bridge composes `OrtYuNetDetector → FivePointAligner → OrtSFaceEmbedder` exactly as the FIR-3 parity tests do; no re-implemented adapter math beyond the xywh→corner conversion at the seam boundary ([SERVE-08], rg-015). **One genuinely new transform exists and is specified here**: bytes→BGR decode (face_pipeline has no byte decoder; the FIR-2 seam takes bytes). The bridge decodes **identically to the incumbent** — exactly `InsightFaceAdapter._bytes_to_cv2`/`_pil_to_cv2` semantics (embeddings/__init__.py:117-128): `Image.open` → `convert("RGB")` if not RGB → `np.array` → `cv2.cvtColor(RGB2BGR)`. **No EXIF transpose** — the incumbent performs none (repo-wide grep clean), and adding it would create decode drift. A bytes→array golden fixture generated from the incumbent helper pins the decode at the bridge seam (deterministic input bytes → expected array hash).
- **Bridge embedding contract**: the incumbent contract is `detect()` returns `FaceDetection` **with populated `embedding`** (the `EmbeddingGeneratorProtocol` backup path receives media_id bytes, not crops — it cannot feed SFace). Therefore `FacePipelineFaceDetector.detect` runs detect→align→embed **one-pass** and always returns embeddings; the profile's generator-protocol slot is filled with `UnavailableEmbeddingGenerator("face_pipeline embeds in detect()")` — no dual pipeline, no unfeedable class ([SERVE-01]).
- **Timeouts + breaker parity with incumbent**: two layers, matching the incumbent exactly — (1) decode/detect/align/embed run in an executor (`run_in_executor`; asyncio timeout alone cannot cancel a running sync ORT `session.run`, so the timeout is bound-the-await, not bound-the-thread — stated, not hidden), (2) `wait_for_adapter` + named `create_adapter_circuit_breaker` wrappers as `InsightFaceFaceDetector` has ([RES-02], [RES-03], [RES-04]). Executor use is bounded by a **dedicated executor with explicit `max_workers`, shared by the bridge in every process that runs it** — worker `max_concurrency` does not cover the HTTP builder or inline task paths, so default-pool reliance is not acceptable; pool saturation is the residual risk and gets a named log/metric.
- **Process-wide runtime singleton**: mirroring `get_shared_insightface_adapter`, the bridge exposes `get_shared_face_pipeline_runtime()` (memoized on profile+models_dir+thresholds, double-checked lock, test reset hook) so the HTTP per-request path cannot re-open ORT sessions or re-read model bytes per scan; a failed load caches the `Unavailable*` outcome, preserving atomic activation ([SERVE-01], [COST-04]).
- **Atomic profile activation**: YuNet and SFace verify/load independently, but the factory treats detector+aligner+embedder as **one unit** — any load/verification failure yields `Unavailable*` for the whole profile; a detector without its embedder must never emit detections ([RLSE-05]).
- **Pose non-parity documented**: `RawDetection` carries no pose; face_pipeline detections stamp `pose_*=None`, so quality scoring differs systematically across profiles — cross-profile quality metrics are non-comparable and S4 labels them per-profile ([PROV-06]).
- **Rollback is the flag** ([RLSE-08]): flag off returns to incumbent instantly; no schema change in this task, `embedding_model` column exists since FIR-2, so old-path code reads new-path rows and vice versa ([DATA-03] — no migration, greenfield policy). ORT-bump rollback = pin revert.
- **ORT bump is behaviour-changing until proven otherwise** ([SERVE-07]): `onnxruntime>=1.16` → `>=1.22` (and `onnxruntime-gpu` mirror) merges only with **both** gates green: (a) the FIR-3 parity suite executed **models-present** — all ORT-executing tests are `@skipif(not MODELS_PRESENT)` and the ONNX bytes are gitignored, so a bare CI run passes vacuously; the gate is `fetch_face_pipeline_models.py` first, then `pytest -rs` with **zero `MODELS_SKIP` skips asserted and recorded**; and (b) an **incumbent co-gate** — onnxruntime is a core dep executing the live buffalo path, which the face_pipeline suite never imports: in a scratch venv with the insightface extra, run at least one **multi-face** fixture plus a single-face fixture on the old and bumped ORT; assert detection **count stability** and per-face embedding cosine ≥ 0.999999; record the ORT version pair and fixture IDs in the slice decision; any deviation is investigated, not tolerated. `make check-remote` runs the model-gated tests as skips — that is inventory, not the gate ([TEST-08], [EVAL-08]).
- **Model bytes in test envs**: CI/check-remote never fetches models; every slice gate that claims parity or bridge E2E coverage must name a models-present local run with recorded evidence (test output showing 0 skipped in the model-gated set). Modelless CI covers only pure logic (conversion, manifest mapping, dim guard, settings validation).

In FIR-4 the dark image continues to ship no face_pipeline models; `scripts/fetch_face_pipeline_models.py` gains `--verify-only` (exit non-zero on missing/hash-mismatch) used by dev/eval provisioning and the deploy runbook for dark environments; wiring fetch+verify into the image build is FIR-6 work (when the model becomes the production path). **Image deps resolve from the checked-in `uv.lock`** via `uv sync --frozen --no-dev --extra bench --no-install-project`, then install the app package with `pip install -e . --no-deps --no-build-isolation` into `/opt/venv` so PEP 517 cannot resolve build requirements outside the lock ([DEP-01], [DEP-02], [SERVE-07], [PROV-08]).
