## Problem Statement

The shipped candidate pipeline (YuNet detect + SFace embed, Apache-2.0, 128-D) is occlusion-weak. Golden-150 (v6.1, source run `face-run-20260723-074749`, **frozen into the single canonical baseline path `benchmarks/results/golden150-fir7-baseline-v6.1/`** — see the Slice-0a freeze step) measured, at leg=candidate:

- **Detection recall 0.504** on clean human-verified boxes (186/375 faces missed) — the detector is the dominant failure *even before occlusion*, and 0.504 is the real ceiling on end-to-end identification (FIR7PR-08). An occluded face YuNet never finds never reaches SFace, so recognizer-only work is capped.
- Synthetic occlusion recovery `a_s`: masked 0.321 (54/84 re-detect miss), sunglasses 0.226 (49/84), occlusion_other 0.643 (5/84). Real-occlusion legs sit at floor-limited n.

Two structural traps make the naive framing dangerous, and this plan is built to avoid them:

1. **The eval can measure the renderer, not the model (FIR7PR-01).** Training twins and eval twins are both produced by `synthetic_occlusion.py`. If they share occluder assets and render-parameter distributions, a high synthetic `a_s` proves only that the adapter memorized *our renderer*, not that it generalizes to real masks. Synthetic `a_s` is therefore demoted to a **DIAGNOSTIC** signal; the claim-bearing legs are real-occlusion + an alternate-renderer stress leg.
2. **Objectives isomorphic to the gate metric Goodhart the gate (FIR7PR-02, EVAL-07/-08/-15).** Selecting checkpoints or hyperparameters on the same synthetic score the gate reports turns the gate into a training target. The plan seals a one-shot held-out eval and confines all selection to a train-split synthetic validation stream.

The commercial ceiling reference (InsightFace/buffalo) is non-commercial weights **and** non-commercial outputs; buying a license or launching the GPU retrain campaign (SCRFD-architecture detector + AdaFace-style 512-D embedder — see Escalation) are both heavier than a targeted, parameter-efficient adaptation of the already-owned Apache 128-D stack that we own outright — *if* Slice 0 proves config levers (including clean-license detector swaps and person→face cascade) cannot close the gap first.

## Constraints

- **[C-EVAL-DISJOINT] Train/eval renderer disjunction (eval integrity, FIR7PR-01).** Training twins and eval twins MUST draw from **disjoint occluder asset pools and disjoint render-parameter distributions**: separate mask/sunglasses atlases, disjoint placement/scale/rotation/blend/lighting ranges, and separately content-hashed occluder packs (`occluder-pack-train-*` vs `occluder-pack-eval-*`). The same disjunction applies to SAM real-asset packs: **`sam-pack-train-*` vs `sam-pack-eval-*`** (disjoint real-asset pools, param ranges, and content hashes). The generator refuses to emit an eval twin from a train-pack asset (and vice versa); a manifest **pack-disjunction test** asserts pack-hash disjunction for both synthetic occluder packs and SAM packs. A claim-bearing SAM/independent-renderer leg is valid only when its SAM assets **never appeared in training**. Synthetic `a_s` is a **DIAGNOSTIC-tier** signal only. The **claim-bearing** occlusion legs are the real-occlusion legs plus an **alternate-renderer stress leg** (see [C-INDEP-SIGNAL]). Pack authoring + disjunction tests land in Slice 1; the gate that consumes them is committed in Slice 0a (below).

  **Residual Leakage Risk (FIR7PLR-G01) — disjoint ASSETS ≠ disjoint render DISTRIBUTION.** Disjoint occluder packs and param ranges do **not** make train and eval twins independent samples, because both are produced by the **same** code path: the same `synthetic_occlusion.py` compositing/blending math, the same frozen-landmark-cache placement geometry, the same clean-base image domain (Golden-150), and the same lighting/warp code. An adapter can overfit to *those* shared artifacts (blend seams, warp interpolation signatures, the clean-base distribution) and score high synthetic `a_s` on eval twins it has effectively already seen the renderer of. Therefore **synthetic `a_s` cannot certify occlusion robustness even with fully disjoint asset packs** — it is a renderer-recovery diagnostic, nothing more.
- **[C-INDEP-SIGNAL] At least one genuinely independent occlusion signal before any robustness claim (FIR7PR-01 / FIR7PLR-G01).** The claim-bearing gate leg MUST include **at least one occlusion signal that does not share FIR-7's compositing code path**: either (a) an **independently-authored occluder render path** (a second compositor — different placement/blend implementation, ideally different author, not a re-parameterization of `synthetic_occlusion.py`), OR (b) a **small consented real-occlusion holdout** (real masked/sunglasses faces from the consented corpus). The alternate-renderer stress leg satisfies (a) only if it is a distinct code path, not merely a distinct pack fed to the same compositor.

  **Preferred path for (a) — SAM real-occluder compositing (named, preferred [C-INDEP-SIGNAL] path; QA v2 §SAM).** A SAM-family cutter (SAM / SAM2 / MobileSAM / EfficientSAM — all Apache-2.0, verified in the QA doc §SAM) segments **real** occluder assets (real masks / sunglasses / hands from license-clean photos) and a *separate, independently-written* compositor places them onto clean faces (MLDATA-10: match training degradation to target stats). This is **offline tooling only** — SAM never enters the runtime path. Independence is **COMPOSITING-CODE-ONLY**: the SAM cutter + compositor (`scripts/train/occlusion/sam_occluder_factory.py`) must not import or call `synthetic_occlusion.py` or `landmark_cache` (placement derives from its own segmentation-driven geometry, enforced by the independence import-graph test); it does **not** claim a fully independent domain — the clean-base Golden-150 image domain remains shared, and only a real-occlusion holdout removes that shared base. Real-asset occluders still shrink the renderer-signature leak (FIR7PLR-G01). **CPU cost:** MobileSAM / EfficientSAM are CPU-feasible offline; this factory runs on the OCI CPU box or the rented GPU, **never the M1**.

  **Model-card hard cap:** an artifact whose only occlusion evidence is synthetic twins from FIR-7's own compositor is stamped exactly `synthetic-twin-recovery under renderer R only — NO robustness claim`; it may ship as a candidate but no card field, demo, or report may attach robustness language to it. A robustness claim requires a CONFIRMATORY cell from an independent signal (real-occlusion or independent-code-path renderer whose SAM/eval assets never appeared in training) with reported N and CI.
- **[C-GATE] Hard, fail-closed re-gate recorded before any sealed touch (FIR7PR-06).** The machine-checkable gate specification is committed in **Slice 0a** (before Slice 0's sealed candidate touch and before any Slice-2/3 training). Slice 0's sealed touch is **illegal** until `benchmarks/gates/fir-7-regate.json` exists on-branch. It has two tiers:
  - **MUST-pass (fail-closed, every artifact):** clean-face paired non-inferiority on all floors (per-floor table below; pairing is **GT-anchored**; each floor states its **harm direction** — see [C-NONINF]), provenance/license audit passing, train/eval leakage checks passing (including SAM pack disjunction + occluder-asset licenses), PEFT/partial-freeze (trainable-fraction ≤ cap), and — for the recognizer — a frozen-base assertion. For the **detector** specifically, MUST-pass also includes **gated FP-rate and IoU thresholds** (not merely "reported"): clean-face detection FP-box count must satisfy **UB(Δ_FP) ≤ +δ_FP** (harm-up), and mean box IoU on the base∩adapted re-detected GT intersection must satisfy **LB(Δ_IoU) ≥ −δ_IoU** (harm-down; intersection size reported). Provisional `δ_FP` / `δ_IoU` come from Slice-0a `p_disc_prior` MDEs (not observed pairwise p_disc) and are committed to the gate spec — a detector that recovers occluded misses by loosening into extra false boxes or looser localization **fails the gate**.
  - **MUST-for-any-robustness-claim:** a CONFIRMATORY improvement on an **independent occlusion signal** ([C-INDEP-SIGNAL] — real-occlusion, or an independent-code-path renderer at n≥floor whose SAM/eval assets never appeared in training) with reported N and paired CI. Absent that, the artifact's model card is stamped exactly `synthetic-twin-recovery under renderer R only — NO robustness claim`; such artifacts may ship as candidates but carry no robustness language (own-compositor synthetic `a_s` alone never licenses a claim).
  A failure of any MUST-pass condition fails the slice regardless of occlusion gain. No `enforce=False` equivalent — the gate is fail-closed.
- **[C-NONINF] PAIRED non-inferiority on GT-anchored units (FIR7PR-03 / FIR7PLR-G02, CACE / EVAL-08, AUDIT-11).** The v2 two-sample one-sample-Wilson / TOST framing is **withdrawn as statistically infeasible**: at baseline p0≈0.504 with n=375 the Wilson half-width is ≈0.051, so the lower bound *at true equality* is ≈0.453 — already below the 0.484 (baseline−0.02) bar. That test cannot certify "no regression"; it can only be passed by a ≈+0.03 *improvement*, which is not what non-inferiority means. It is **replaced by a within-subject PAIRED test**, which is valid here precisely because every re-gate re-embeds the **identical** corpus ([C-REEMBED]) and pairing is defined on **ground-truth labeled faces**, not detector-native boxes. The phrase "within noise" remains **banned** unless it resolves to the rule below.

  **GT-anchored pairing unit (survives detector A/B swaps and cascade).** The pairing unit is a **ground-truth labeled face**. A **detection hit** is defined as: the GT face is matched by a predicted box at the committed IoU threshold. That definition is well-defined for **any** detector, so the 2×2 table remains valid under Detector A/B swaps and person→face cascade — never pair on detector-native box ids that would break across model swaps.

  **Harm direction (every floor).** `Δ := metric_adapted − metric_base`. Where **higher is better** (recall, precision, purity, BCubed F, IoU, cascade accuracy), harm is *down*: gate on **LB(Δ) ≥ −δ**. Where **higher is harm** (FNIR, FP-rate / FP-box count), harm is *up*: gate on **UB(Δ) ≤ +δ**. Never apply the lower-bound rule to an up-is-harm metric (that is fail-open). Each row in the per-floor table names its harm direction next to its PASS rule.

  **Binary floors** (detection hit; correct-ID; correct-reject) — for each floor classify every GT-anchored paired face into the 2×2 table `{both-correct, both-wrong, b = base-correct/adapted-wrong (regression), c = base-wrong/adapted-correct (recovery)}`. Concordant pairs (both-correct, both-wrong) carry no information about the delta, so the delta's uncertainty is driven only by the **discordant** count `b+c` — this is why pairing is dramatically more powerful than comparing two independent 0.5±0.05 proportions. The non-inferiority rule is the **conjunction** of two conditions, both must hold (one α_floor spend — dual tests are a conjunction, not two family-wise tests):
    1. **Margin-McNemar (Tango score form).** Test one-sided H0: `P(regress) − P(recover) ≥ δ` vs H1: `< δ` at `α_floor` via the **exact / mid-p conditional binomial on discordant pairs with the margin offset** (or equivalently the Newcombe/Tango score CI on `Δ = (c−b)/n` against `−δ`). **Tango's score test** is the canonical implementation of the margin form; cluster-robustness is via **cluster-bootstrap over images/identities** (recomputing `(b,c)` each resample). PASS = reject H0 at `α_floor`.
    2. **Paired-difference CI (harm-down floors).** The **Newcombe/Tango paired (score) CI** for `Δ = p_adapted − p_base = (c − b)/n` must have **LB(Δ) ≥ −δ** (equivalently: the CI upper bound on `(base − adapted)` ≤ `δ`).
  **Detector FP-rate gate (paired, per-image; harm-up).** FP-rate is **not** a per-GT-face binary: it is the **per-image paired FP-box count** (predicted boxes that match no GT face at the IoU threshold). Gate with a **cluster-bootstrap over images** recomputing the paired FP delta each resample: **UB(Δ_FP) ≤ +δ_FP** (FP count must not rise beyond δ_FP). Do **not** gate on LB(Δ_FP).
  **Detector IoU gate (paired continuous, intersection-reported; harm-down).** IoU is a paired continuous delta on the **base∩adapted re-detected GT intersection** (GT faces hit by both base and adapted at the IoU threshold). Report the **intersection size** so denominator shrinkage is visible. Gate with a bootstrap-over-images paired CI requiring **LB(Δ_IoU) ≥ −δ_IoU**.
  **Cluster design effect (AUDIT-11).** Golden-150 draws multiple faces per image, so discordant pairs cluster within images/identities. Both the margin-McNemar / Tango test and the paired CI use the cluster-robust form (**cluster-bootstrap resampling images/identities**, recomputing `(b,c)` on each resample), reporting effective discordant `n_eff = (b+c)/deff` — never treating discordant faces as independent.
  **Non-binary floors** (clustering purity, BCubed F, unknown-rejection FNIR@fixed-FPIR) have no per-face 2×2 table; gate them with a **bootstrap-over-identities paired CI**: resample identities with replacement, recompute *both* base and adapted metrics on the **same** resampled identity set each iteration, form `Δ = metric_adapted − metric_base`. **Harm-down floors** (purity, BCubed F): require **LB(Δ) ≥ −δ**. **Harm-up floors** (FNIR@fixed-FPIR): require **UB(Δ_FNIR) ≤ +δ** — FNIR must not rise beyond δ; gating FNIR on LB(Δ) ≥ −δ is fail-open and forbidden.
  **Setting δ per floor (two-stage p_disc protocol; baseline-only freeze cannot observe p_disc).** `p_disc = (b+c)/n` is **pairwise** (base vs adapted) and is **not** computable from a baseline-only freeze. Pre-register δ in two stages: **(i) Slice 0a locks, per floor:** the base value, `n` and the cluster structure (`deff` / `n_eff` basis), a **conservative plug-in `p_disc_prior`** (pre-registered constant, e.g. `0.10`, justified by the worked example below), and the resulting **provisional `δ_floor := max(0.02, MDE_paired(n_eff, p_disc_prior))`** rounded up to 0.005, where `MDE_paired ≈ (z_{α} + z_{β})·√(p_disc_prior)/√(n_eff)` at power 0.8. **(ii) At each SEAL:** record the **actual `p_disc` observed** in that paired run and **report the achieved MDE** alongside the gate outcome (transparency only). **`δ_floor` stays the pre-registered provisional value — no post-hoc δ re-tuning.** Worked example (also the justification for `p_disc_prior=0.10`): at `n_eff≈300`, `p_disc_prior=0.10`, one-sided `α=0.05` (`z=1.645`), power 0.8 (`z=0.84`): `MDE ≈ 2.485·√0.10/√300 ≈ 2.485·0.316/17.3 ≈ 0.045` → provisional `δ≈0.045`. Because the paired SE `≈√(p_disc)/√n_eff` is far below the two-sample SE `≈√(2p(1−p)/n)`, a **δ in the 0.02–0.045 band is achievable**. Trained artifacts run **≥2 seeds**; the reported band is the seed envelope and the gate must hold on the worst seed. Concrete per-floor base values, `n`/`n_eff` bases, `p_disc_prior`, and provisional `δ` are locked in Slice 0a into `fir-7-regate.json`. See the per-floor table under Verification Strategy.
- **[C-SEALED] Sealed one-shot eval + train-split-only selection + PROGRAM-LEVEL budget (FIR7PR-02 / FIR7PLR-G03, EVAL-07/-08/-10).** The Golden-150 gate eval is **pre-registered and sealed**: run **once per candidate artifact**, never used for checkpoint or hyperparameter selection. All checkpointing, early-stopping, and hyperparameter selection read a **train-split synthetic validation** stream only (identity-disjoint from the **sealed eval split** — see Terminology). Beyond per-artifact sealing, a **program-level evaluation budget** governs the whole task to control family-wise error across S0/S2/S3 (v2's "count the peeks" alone lets reused sealed evals inflate family-wise error; Slice 4 reports already-sealed results and does **not** consume new seals):
  - **Pre-registered budget + explicit K=3 unit set.** The gate spec (`benchmarks/gates/fir-7-regate.json`, committed in Slice 0a) fixes, before any sealed touch: the **candidate cap K** and a **total sealed-evaluation count** = K (one seal per committed candidate, no more). **K = 3** units are exactly: (1) the **Slice-0 stacked config candidate**, (2) **`yunet-occ`**, (3) **`sface-occ-adapter-or-joint`** (the recognizer adapter alone, or a pre-registered joint detector+adapter artifact — not both as separate seals). If a distinct joint artifact is desired, it must be **pre-registered as one of these three K candidates** in the gate spec; it cannot be an unbudgeted fourth seal. Slice 4's head-to-head **reports already-sealed results only** — no new seals.
  - **Alpha budget (spending) — concrete split.** Family-wise `α_total = 0.05` with **K=3** sealed candidates → **`α_candidate = 0.05/3 ≈ 0.0167`** each. Within a candidate, **`α_floor = α_candidate / F`**, where `F` = number of **MUST-pass gated floors for that artifact class** (only floors that can fail the seal; DIAGNOSTIC / reported-only rows do not spend α). **Dual tests within one floor** (margin-McNemar **AND** CI) are a **conjunction at the same `α_floor`** — no extra spend. Worked examples: **detector** (`yunet-occ` / stacked detector leg) gated floors F=4 → detection recall, FP-rate, IoU, cascade → `α_floor ≈ 0.0167/4 ≈ 0.0042`; **recognizer** (`sface-occ-adapter`) gated floors F=5 → ID precision, ID recall, FNIR, purity, BCubed → `α_floor ≈ 0.0167/5 ≈ 0.0033`. The Slice-0 stacked config candidate spends α across whichever MUST-pass floors its artifact class touches (detector + recognizer floors if both legs move). Per-floor `α_floor` is read from this budget into `fir-7-regate.json`, not chosen ad hoc.
  - **Burn-after-use.** Every sealed evaluation — **including a FAIL** — consumes one unit of the K budget and its α share. A failed seal does **not** refund budget; you cannot mint unlimited candidates and keep re-sealing until one passes.
  - **Exhaustion rule.** When the K/α budget is spent, **stop**: the **default disposition is escalation to the retrain campaign** (report the best-sealed artifact with its consumed-alpha caveat, or `no-pass within budget`). Raising K is **never** proposed as first resort; K may rise **only** via an operator-sign-off gate-spec change recorded under [C-SEALED] before the next seal.

- **Determinism + reproducibility (rg-015, PROV-01).** Training is seeded and logged; produced weights are content-hashed and carry a model card. Eval is the existing Golden-150 harness — do not invent a parallel scorer.

## Workflow Principles

- **Measure against a frozen baseline, on the claim-bearing leg.** Every slice reports the Golden-150 delta vs the frozen v6.1 candidate baseline. Robustness deltas are read from an independent occlusion signal ([C-INDEP-SIGNAL]): the real-occlusion leg, and the independent-code-path/alt-renderer leg **which is claim-bearing (CONFIRMATORY) only at n ≥ its reported floor, else DIRECTIONAL** (single resolution of the v2 tier ambiguity — it is not both). Synthetic `a_s` from FIR-7's own compositor is DIAGNOSTIC context, never the success number.
- **Selection and gating are different data.** Selection reads train-split synthetic validation; gating reads the sealed held-out eval once. Never cross the streams (EVAL-07/-10).
- **The eval harness is the source of truth.** Reuse `scripts/eval_harness` (twin renderer, `score-face`, floors, tier logic). The training-data generator is the SAME twin machinery — but with **disjoint train/eval occluder packs and identity split** ([C-EVAL-DISJOINT]).
- **Frozen base for the recognizer is a guard, not a proof.** SFace weights are never updated. This is a *forgetting guard*, but "LQ↑ without HQ↓" is a **measurement obligation** (AdaFace FAIR-NN), not "true by construction" — the adapter sits after the backbone and can still move clean embeddings, so clean preservation is tested per-epoch and at the gate (FIR7PR-04).
- **One legal owner of the data manifest.** A single dataset-provenance manifest declares every training source and its license; nothing enters training that is not in it and license-clean.
- **Cascade honesty (FIR7PR-08/-09, EVAL-16).** Detection failures count as identification errors in at least one reported end-to-end cascade metric. `a_s` is reported on a fixed denominator (faces re-detected by *all* legs) alongside a separate detection-coverage number, so a detector change cannot silently inflate `a_s` by moving its own denominator (EVAL-19).
- **No silent capability inflation.** Candidate weights and their sealed gate evidence ship together; no demo or claim references adapted-model numbers, or quotes a DIRECTIONAL/synthetic cell, without the tier label (FIR7PR-14).

## Terminology

- **Adapter**: a small trainable module (embedding-space residual bottleneck or low-rank conv delta) added to a frozen backbone; trained on the narrow occlusion target while the base is unchanged.
- **Mask-invariant adapter**: recognizer adapter trained so `embed_adapted(occluded)` matches the base clean template of the *same* identity while a margin term keeps *different* identities separated (see Slice 3 loss).
- **Twin**: a synthetic occluded render of a clean base face (mask / sunglasses / other) from a frozen landmark cache; the (clean, occluded) pair is the training and eval unit. **Train twins and eval twins use disjoint occluder packs** ([C-EVAL-DISJOINT]).
- **Occluder pack**: a content-hashed set of occluder assets + a render-parameter distribution. `occluder-pack-train-*` and `occluder-pack-eval-*` are disjoint. The **independent-code-path / alternate-renderer** signal ([C-INDEP-SIGNAL]) is a distinct *compositor code path* (not merely a third pack fed to `synthetic_occlusion.py`); its leg is **claim-bearing (CONFIRMATORY) only at n ≥ floor, else DIRECTIONAL**. The preferred independent path is the **SAM occluder factory** (real-asset cut + independent compositor).
- **SAM occluder factory**: offline tooling (`scripts/train/occlusion/sam_occluder_factory.py`) that uses a SAM-family model (Apache-2.0) to segment real occluder assets and a *separately written* compositor to place them. Independence is **compositing-code-only** ([C-INDEP-SIGNAL](a)): import graph must exclude `synthetic_occlusion` and `landmark_cache`; placement from segmentation-driven geometry only. Packs: `sam-pack-train-*` / `sam-pack-eval-*` (disjoint). Never runtime.
- **Person→face cascade**: Apache-verified person detector (RT-DETR / D-FINE / PP-PicoDet; **not** Ultralytics AGPL) proposes person boxes; face detection re-runs on upscaled person crops; union with full-frame detections. Slice-0 detection lever attacking small/occluded-face recall.
- **Detector A/B lever**: drop-in swap of the face detector. Candidates are registered as **detector ids in `config_levers.py`** with **pinned weight paths** and matching **`license_policy.py` entries verified at ingest** (not QA-doc prose alone). Per-lever proxy metrics come from the train-split synthetic proxy sweep (`benchmarks/results/levers-proxy-sweep-*/`); only the single stacked candidate produces a sealed Golden-150 row. Not a training run.
- **Re-detect miss**: an occluded twin the detector fails to re-detect after occlusion is applied; the dominant candidate failure mode.
- **`a_s` (fixed-denominator)**: synthetic occlusion recovery accuracy over the **intersection of faces re-detected by all compared legs**, at the entity-disjoint transferred τ (CAL-07). Reported with a separate **detection-coverage** number. **DIAGNOSTIC tier** (FIR7PR-01/-14). Intersection-based `a_s` is for **leg-to-leg comparison tables only**; descope thresholds pin denominators exclusively to the **frozen baseline's re-detected set** — see Slice 0.
- **Cascade identification metric**: end-to-end accuracy where a face any stage failed to detect/associate counts as an identification error (EVAL-16). The claim-bearing operational number.
- **Evidence tier**: every gate cell is labeled **CONFIRMATORY** (real-occlusion, n ≥ threshold, sealed), **DIRECTIONAL** (real-occlusion n below threshold, or a single-seed peek), or **DIAGNOSTIC** (synthetic / renderer-coupled). Success language may not quote DIRECTIONAL or DIAGNOSTIC cells without the label (FIR7PR-14).
- **Train/eval identity split**: **train-split** = train partition of Golden-150 identities **+ synthetic identities**; **sealed eval** = eval partition of Golden-150 identities only (+ eval-pack / sam-pack-eval occluders). Occlusion training and the lever **proxy validation stream** use only train-split identities and train-pack occluders; the proxy stream is **identity-disjoint from the sealed eval split** (not merely "disjoint from Golden-150" as a whole). The sealed eval never sees a trained identity or a trained occluder as a probe. The **split artifact** is a **committed split manifest with content hash**, generated in **Slice 0a** and consumed by Slice 0's proxy stream and Slice 1 — never produced on first use mid-pipeline.

## Target Outcome

The occlusion gap closed to target **with zero clean-face floor regression** (per-floor non-inferiority, [C-NONINF]), achieved by the **cheapest sufficient lever** and proven on a **sealed one-shot Golden-150 re-gate**. The end-state is one of three, all valid PASSes:

1. **Slice-0 close (preferred, cheapest):** config/pooling levers close the gap; the `TRAINING_DECISION` artifact records "no training needed"; no new weights are produced. PASS.
2. **Detector-only:** `yunet-occ` (Apache-clean, PEFT/partial-freeze) closes the dominant re-detect-miss gap; the recognizer stays base. PASS if the cascade metric improves under [C-NONINF] and the recognizer floors are unregressed.
3. **Detector + recognizer:** `yunet-occ` then a frozen-base `sface-occ-adapter`, sequenced (detector first, recognizer trained on updated crops). PASS if both clear their MUST-pass conditions and at least one carries a real-occlusion robustness claim (or an explicit synthetic-only stamp).

Any produced artifact is Apache-clean, content-hashed, carries a schema-valid model card, is integrated behind the existing model-swap seam with a **working, unit-tested rollback to base weights** (RLSE-10), and is stamped with a distinct `embedding_model`/detector id under a mixed-space guard. Final ship decision deferred to FIR-6's gate. **Embedding dimensionality stays 128-D** for all FIR-7 artifacts.

### Escalation & Non-Goals: the GPU retrain campaign

Per the QA v2 bottom line, the proprietary end-state is exactly **two retrains** — an SCRFD-architecture detector and an AdaFace-style **512-D** embedder (margin loss per distilled `adaface.md` FAIR-NN), trained on synthetic+consented data, weights **server-side** (structural moat). FIR-7 is the **cheaper rung** on the FM-05 ladder:

1. config levers (thresholds, tiling, pooling),
2. clean-license detector swaps + person→face cascade (Slice 0),
3. PEFT adapters on the existing **128-D** stack (Slices 2–3).

FIR-7 does **not** change embedding dimensionality (stays 128-D; 512-D belongs to the retrain campaign; **768/1024-D rejected outright** — distance concentration + ANN index decay toward linear scan; FaceNet ablation 128 ≥ 512; capacity goes to backbone/data/loss, not head width — distilled `bruch-vector-retrieval.md` + `zezula-similarity-search.md`). If the sealed gate says adapters cannot close the gap, the disposition is **"escalate to the retrain campaign task (future FIR task, own plan)"** — NOT deeper adapter work and NOT raising K. Named failure-mode disposition in Slice 4.
