# 2025-12-15 — Canonical Recognition Report + Regression Harness

Author: OpenAI GPT-5.2

## Why this exists

Accuracy is declining and it’s currently hard to tell whether a change improved clustering or simply shifted manual curation work around. The goal is to create a **repeatable testing harness** that can detect progress/regressions in the recognition/clustering pipeline without requiring re-labeling every time.

This document proposes a “canonical report” that is generated **after** the user finishes labeling clusters and doing merges/splits, and a harness that compares future runs against that canonical snapshot.

## Definitions (so metrics are unambiguous)

- **Identity**: one detected face record (`media_identities`), i.e. a face bounding box on a media item.
- **Identity locator**: stable identifier for a face across DB resets: (`media_id`, `bbox_x`, `bbox_y`, `bbox_width`, `bbox_height`).
- **Cluster**: `identity_clusters` grouping of identities.
- **Labeled cluster**: `identity_clusters.user_confirmed=true` (and usually `label` non-null).
- **Canonical label**: the human “ground truth” class, derived from labeled clusters after curation is complete.
- **Original assignment**: the cluster an identity was assigned to by the pipeline before any manual curation.
- **Curation actions**:
  - **Merge**: entire cluster A merged into cluster B.
  - **Split**: identities moved out of a cluster into other cluster(s) (manual remove/assign).
  - **Wrong person (contamination)**: identities that ended up removed from a labeled cluster (false merge symptom).
  - **Fragmentation**: multiple original clusters that should have been one canonical label (false split symptom).

## Proposed output: Canonical report (what it must contain)

The report needs to do two jobs:

1. Act as **ground truth** for a fixed dataset (so future runs can be evaluated automatically).
2. Act as an **error attribution dataset** (so we can tell which pipeline stage/method produced mistakes that the user had to fix).

### Important detail: stable identity matching

If you reset the DB and re-run face detection, `media_identities.id` will change. For regression testing, the harness must match identities across runs using a stable locator:

- (`media_id`, `bbox_x`, `bbox_y`, `bbox_width`, `bbox_height`) from `media_identities`

This assumes face detection is deterministic enough for the dataset. If bbox drift becomes an issue, the next step is to also store a **crop hash** (hash of the face crop bytes) to match robustly.

## How to generate the canonical report (implementation plan)

### Phase 1 (DB-backed “runs + events”)

Goal: stop depending on logs by persisting a minimal run/event model.

1. Add DB tables (or a single JSONB event table):
   - `recognition_runs`: `id`, `tenant_id`, `created_at`, `git_sha`, `settings_snapshot`, `dataset_selector`
   - `recognition_events`: `id`, `run_id`, `ts`, `event_type`, `payload` (JSONB)
2. Emit events from the pipeline (at least):
   - `assignment_decision` (ALWAYS includes `identity_id` + `identity_locator`, decision, method, similarity, confidence, threshold, gate pass/fail, and best_rep locator when applicable)
   - `cluster_created` (cluster_id + identity_locators of initial members, plus creation_method)
   - `cluster_merged` (source_cluster_id, target_cluster_id, moved_count; persist moved `identity_id`s and/or `identity_locator`s when feasible)
   - `identity_moved` (`identity_id` + `identity_locator`, from_cluster_id, to_cluster_id, reason=user_action)
   - `cluster_renamed` (cluster_id, old_label, new_label)
   - `graph_run` (algorithm selection + parameters + outputs: clusters/outliers/edges, anchors injected)
   - `representatives_snapshot` (cluster_id, rep_count, and representative `identity_id`s + `identity_locator`s + scores)
   - `representatives_recomputed` (cluster_id, rep_count_before/after, selection_method, selected representative identity_locators)
3. Implement `generate_canonical_report` as a CLI script:
   - location: `apps/prototype-description-service/scripts/`
   - input: `--tenant-id`, `--run-id`, optional `--roster-id` or `--media-id-file`
   - output: `data/canonical_reports/<tenant>/<run_id>.json`

This makes the report reproducible and makes per-method attribution straightforward.

## Regression harness (how future runs get scored)

### Inputs

- `canonical_report.json` (ground truth)
- a new run’s assignments for the same dataset (from `recognition_events` or a DB export)

### Core scoring approach (label-permutation safe)

For clustering, avoid “accuracy by label name” because predicted clusters are unlabeled. Use permutation-invariant metrics:

- **Pairwise precision**: among identity pairs predicted in the same cluster, how often do they share the same canonical label? (penalizes false merges)
- **Pairwise recall**: among identity pairs with the same canonical label, how often are they predicted in the same cluster? (penalizes fragmentation)
- **Pairwise F1**
- Optional: ARI / VI / B-cubed (nice-to-have)

### Curation cost metrics (closest to UX pain)

Derived from canonical vs predicted membership:

- **Fragmentation per canonical label**: number of predicted clusters that contain identities of this label
- **Contamination per canonical label**: number of predicted clusters that mix this label with others (or % mixed identities)
- **Estimated merges needed**: predicted_cluster_count_per_label - 1
- **Estimated removals needed**: count of identities in a predicted cluster whose canonical label ≠ cluster’s majority canonical label

### Output

- `metrics.json` (machine-readable)
- `summary.md` (human-readable)
- optional plots (see below)

## How to graph clusters and pipeline efficiency

These visualizations make regressions obvious:

1. **Sankey / alluvial diagram (best ROI)**

   - left: original predicted clusters
   - right: final canonical labels
   - edge width: # identities moved
   - immediately shows fragmentation and contamination

2. **Confusion matrix heatmap**

   - rows: canonical labels
   - cols: predicted clusters (after Hungarian/majority mapping)
   - highlights which identities are swapped/mixed

3. **Cluster size distribution over time**

   - histogram of cluster sizes (especially singleton ratio)
   - track “singleton explosion” regressions

4. **Embedding projection (UMAP/t-SNE)**

   - points = identities
   - color by canonical label; outline by predicted cluster
   - reveals overlap regions and “bridge” faces that cause merges

5. **Curation cost dashboard**
   - merges/splits/removes per canonical label
   - time-to-curation (if timestamps persisted)

Implementation-wise, (1) and (2) can be generated entirely from the canonical report + a run export; (4) requires access to embeddings.

    4. Build cluster_outcomes by diffing original cluster assignments vs final curated state.
    5. Compute summary metrics.
    6. Write to data/canonical_reports/<tenant>/<run_id or timestamp>.json.

#### 2. `evaluate_run.py`

```python
# Location: apps/prototype-description-service/scripts/evaluate_run.py
# Usage: python -m scripts.evaluate_run --canonical <path> --run-id <UUID>

def compute_pairwise_metrics(canonical: dict, predicted: dict) -> dict:
    """
    1. Build ground_truth_pairs: {(locator_a, locator_b): same_label}
    2. Build predicted_pairs: {(locator_a, locator_b): same_cluster}
    3. Compute:
       - TP: pairs correctly co-clustered
       - FP: pairs wrongly co-clustered (contamination)
       - FN: pairs wrongly separated (fragmentation)
       - Precision = TP / (TP + FP)
       - Recall = TP / (TP + FN)
       - F1 = 2 * P * R / (P + R)
    """

def compute_curation_cost(canonical: dict, predicted: dict) -> dict:
    """
    For each canonical label:
    - fragmentation = count of predicted clusters containing this label's identities
    - contamination = count of identities in "wrong" predicted clusters
    - estimated_merges = fragmentation - 1
    - estimated_removals = contamination count
    """
```

### Identity Locator Implementation

```python
# Add to recognition/domain/locator.py or a new locator.py

@dataclass(frozen=True)
class IdentityLocator:
    """Stable identifier for matching identities across DB resets."""
    media_id: int
    bbox_x: int
    bbox_y: int
    bbox_width: int
    bbox_height: int
    crop_hash: str | None = None  # SHA256 of face crop bytes (truncated 16 chars)

    @classmethod
    def from_media_identity(cls, mi: MediaIdentity) -> "IdentityLocator":
        # Note: crop_hash requires access to original image or stored hash
        return cls(mi.media_id, mi.bbox_x, mi.bbox_y, mi.bbox_width, mi.bbox_height, mi.crop_hash)

    def matches(self, other: "IdentityLocator", tolerance: int = 5) -> bool:
        """Match with bbox drift tolerance for detection variance."""
        if self.crop_hash and other.crop_hash:
            return self.crop_hash == other.crop_hash

        return (
            self.media_id == other.media_id
            and abs(self.bbox_x - other.bbox_x) <= tolerance
            and abs(self.bbox_y - other.bbox_y) <= tolerance
            and abs(self.bbox_width - other.bbox_width) <= tolerance
            and abs(self.bbox_height - other.bbox_height) <= tolerance
        )
```
