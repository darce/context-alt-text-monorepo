# Plan: v0.2 -- Drift Reconciliation and Conflict Review

## Problem Statement
When local WordPress curation conflicts with backend snapshot data (e.g., the same identity is moved to two different clusters on both sides), a reconciliation mechanism is needed. Currently, there is no way to surface or resolve these conflicts.

## Workflow Principles
- **Curation Precedence**: Confirmed local curation decisions must never be silently overwritten by snapshot data.
- **Human-in-the-Loop**: Conflicts that cannot be resolved via versioning must be surfaced to a user.

## Terminology
- **Drift**: A state where the local projection and the backend ground truth disagree on a confirmed assignment.
- **Reconciliation Queue**: A UI view where users resolve detected drifts.

## Current State Analysis
- The `SovereignProjector` currently overwrites local state with snapshot state (unless the row is missing).
- There is no logging or surfacing of skipped rows during projection.
- Users have no visibility into synchronization conflicts.

## Proposed Solution
Introduce a "Drift Review Queue" in the WordPress admin UI where conflicted cluster assignments are surfaced for human resolution, ensuring local curation remains the authoritative source of truth.

## Patterns to Follow

### [Drift Detection Pattern]

```php
if ( $local_row->is_user_confirmed && $remote_row->version == $local_row->version && $remote_row->label !== $local_row->label ) {
    $this->drift_queue->add( $local_row, $remote_row );
}
```
